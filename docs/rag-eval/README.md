# RAG 检索评测集

用于量化评价知识库检索准确率。**改动检索策略、分块方式或换模型前后，都应跑同一份评测集对比。**

## 目录内容

| 文件 | 说明 |
|---|---|
| `corpus/*.md` | 评测语料（9 篇），模拟校园真实文档。**语料被有意埋入歧义**，见下文 |
| `corpus.json` | 由 `corpus/*.md` 合并生成，供脚本单文件读取 |
| `eval-set.json` | 45 道评测题与金标（含陷阱题型分类） |
| `run_eval.py` | 评测运行器 |

## 快速开始

```bash
cd docs/rag-eval

# 1) 离线自检：关键词基线，不需要启动服务
python3 run_eval.py --strategy keyword

# 2) 建立基线并评测线上服务
python3 run_eval.py --strategy keyword --json > baseline.json
python3 run_eval.py --strategy http --kb-id <知识库ID> --token <Token> --json > current.json

# 3) 对比，判断改动是否真的提升（含逐题退步检查）
python3 run_eval.py --compare
```

语料变更后需重新生成合并文件：

```bash
python3 -c "import json,os;d='corpus';print(json.dumps({n:open(os.path.join(d,n),encoding='utf-8').read() for n in sorted(os.listdir(d)) if n.endswith('.md')},ensure_ascii=False,indent=2))" > corpus.json
```

## 指标口径

| 指标 | 含义 |
|---|---|
| `recall@k` / `mrr` / `ndcg@10` | **章节级**命中：文档与章节都要对上，最严格 |
| `doc_recall@5` / `doc_mrr` | **文档级**命中：只要求召回正确文档 |
| `distractor@1` | top1 命中了标注的干扰文档，越低越好 |
| 拒答题 | 无金标，**不参与召回指标分母**，单独统计 |

**为什么要分章节级与文档级**：两者差距反映问题性质。文档级高而章节级低，说明召回到了正确文件但排序不够准（重排序可解）；文档级本身低，说明向量/词法召回没覆盖（重排序救不了）。这是判断「该加精排还是该修召回」的直接依据。

## 题型设计

常规题（18 题）：`core` 基础事实、`colloquial` 口语化改写、`table` 表格取数、`multi-hop` 跨文档。

陷阱题（23 题），按暴露的弱点分类：

| 题型 | n | 考察点 | 典型设计 |
|---|---|---|---|
| `trap-neighbor` | 4 | 近邻文档混淆 | `repair-dorm` 与 `repair-public` 结构几乎相同，仅凭「宿舍/教室」区分，且时效 3 天与 5 天互为干扰 |
| `trap-same-term` | 4 | 同词异实体 | 「研讨间」同时出现在开放时间文档与预约文档；「学籍证明」vs「在读证明」 |
| `trap-number` | 6 | 数字取错 | 请假审批 1—3/4—7/8+ 三档；场地 3 天/10 天；校园卡与成绩单同为 20 元但不同对象 |
| `trap-negation` | 5 | 例外与限定条件 | 紧急报修不受 3 个工作日限制；考试周延长至 24:00；挂失后找回能否解挂分情况 |
| `trap-false-premise` | 5 | 错误前提 | 「报修先交费吗」「教室能当活动场地吗」「违约要罚款吗」「师傅个人电话是多少」——应纠正而非顺从 |
| `no-answer` | 4 | 超纲拒答 | 游泳馆年卡、国家奖学金、食堂早餐、交换生流程等语料中不存在的问题，应明确拒答 |

### 语料中的埋点

语料不是随手写的说明文，而是刻意制造了检索歧义：

- `repair-dorm.md` / `repair-public.md`：两份报修指南章节结构一致、故障类型有重叠（门窗损坏、家具维修），只有归属词不同
- `library-hours.md` / `library-booking.md`：同为图书馆文档，「研讨间」在两篇都高频出现，一篇讲时间一篇讲规则
- `certificate-enroll.md` / `transcript-notice.md`：三份证明（成绩单/在读证明/学籍证明）用途时效各不相同，两篇互相引用
- `campus-card.md`：同一数字 20 元出现在不同对象上（补卡工费）
- `leave-policy.md`：审批权限只有天数档位差异，边界值（8 天）易错

## 召回改造 A/B 实测（2026-09-15，在真实 PostgreSQL 上按 SQL 复现）

在真实 RAG 库（PostgreSQL 18.6）上用本评测集复现改造前后差异，**41 道计分题**：

| 实现 | R@1 | R@3 | R@5 |
|---|---|---|---|
| 改造前（`simple` 分词全文检索 + 候选内算余弦） | — | — | — |
| 改造后（词法 pg_trgm + 标题加权 RRF 融合） | 28/41 | 35/41 | 38/41 |

改造前**无法计入 R@1/R@5**：41 道题里 `plainto_tsquery('simple', 问题)` 在语料上**命中 0 行**，即零候选。原因是 PostgreSQL 的 `simple` 配置不切分中文，`to_tsvector('simple','图书馆周末开放时间')` 整串成为单个 token，与正文中的连续汉字无法匹配。此时代码会走入 `rows.isEmpty()` 的回退分支（无 `ORDER BY` 的 `LIMIT 40`），**等价于在任意 40 个分块里排序**。

单通道对照（仅词法、无融合）：R@1 27/41、R@5 37/41 —— 说明 RRF 融合相较单通道另有小幅增益。

**尚未验证的部分（重要）**：本次 A/B 只覆盖**词法通道**。`AI_ENABLED=false` 且未配置向量模型，因此向量通道无法端到端实测；SQL 侧的余弦与维度过滤构件已单独验证可用，但**语义召回的真实增益未经验证**。配置向量模型并重建索引后，应重跑本评测集补上这部分数据。

## 当前基线（关键词策略，2026-09-15）

```
题目总数 45（计分 41 + 拒答 4）
章节级：R@1 0.732  R@3 0.951  R@5 0.976  MRR 0.838  nDCG 0.831
文档级：doc_R@5 0.976
干扰率@1 0.122
常规题 R@5 0.941 ／ 陷阱题 R@5 1.000
```

**重要提示：Recall@5 在当前语料规模（9 篇 / 约 40 个检索单元）下已饱和，区分度差；应以 Recall@1 与 MRR 作为主要观测量。** 这与生产环境不同——生产知识库规模远大于此，R@5 会明显下降。

按 Recall@1 看，最弱环节是：

| 题型 | R@1 | 说明 |
|---|---|---|
| `colloquial` | **0.000** | 口语化提问完全无字面重合，如「我们寝室灯不亮了找谁修」 |
| `table` | 0.500 | 表格单元格定位不准 |
| `core` | 0.714 | 与 `transcript-notice` 等近邻文档混淆 |

## 已知局限（避免误用）

1. **语料规模偏小**，R@5 饱和。引入重排序后，应主要看 R@1/MRR 的提升，或补充更多文档扩大区分度。
2. **citation 未自动校验**。`expectedAnswerContains` 目前是人工核对用的参考，脚本只算检索指标不校验答案文本。生成侧准确率（忠实度、引用正确性）需要 LLM-judge 或人工抽检。
3. **拒答题只统计不判分**。当前仅记录其 top1 是否被召回，没有自动判定「是否真的拒答」——那需要调用生成模型。
4. **`http` 策略依赖内容反查归属**。线上分块不含原始章节结构，脚本按二元组最大重叠把分块映射回文档/章节，边界情况可能误判。
5. 中文应按字（而非 token）评估，本脚本已按字符做二元组匹配。

## 扩充建议

- 每新增一篇知识库文档，至少补 2 道题：1 道常规 + 1 道陷阱
- 陷阱题优先从真实误答中提炼（线上「答得不对」的反馈回流）
- 语料与题量到 50 篇 / 150 题后，R@5 才具备稳定区分度
