| 状态 | 含义 |

| **有** | 仓库/工作区存在，本次已验证可用（或命令可复现） |
| **半成品** | 存在但缺关键部分（无 UI、未提交、测试红、配置缺项、仅开发环境可用） |

## 七、交付结论

1. **当前不是“可交付完整项目”，而是“功能覆盖很广、可演示、但交付基线未收口”的工程样机。** 本轮已补齐作业中心最小闭环、角色/组织基础 CRUD（页面已注册，静态 200）、App 动态社区分区、V2_1 + out-of-order 迁移级修复；但版本管理、全新 MySQL 空库验收、生产管理员 bootstrap/SSO、V62 测试债、安全开关、测试、合规、运维等“交付件”仍未完成。
2. **建议先交付“最小可交付包 MDP”**：后端 jar + 迁移 + bootstrap（V2_1 已含，管理员 bootstrap 待补）+ `.env.example` + 生产 compose + Nginx + 管理台（三页已注册，浏览器复验后交付）+ 小程序源码 + release APK + OpenAPI 导出 + 测试报告 + 部署/运维手册 + 演示数据重置 + 安全清单 + 隐私/协议。**作业最小闭环可纳入首单；电费、AI（无 Key 时）、多校区、支付不纳入首单；教师工作台/附件/评分不承诺。**
3. **验收顺序**：先验“部署 + 登录 + 一单报修闭环 + 站内通知”，再验作业/社区/官网通知/大屏；教务、AI、电费作为条件项单独验收。
4. **签约前必须确认**：客户能提供 §6 的材料，尤其是教务/官网/身份授权与 AI Key；否则相关能力只能作为“后续版本”，不能计入首期报价。
5. **交付前最后一件事**：按 §2 逐项复核并重跑 §3 命令；本文所有“半成品/缺/需确认”项在交付版本中应清零或转为合同约定的“后续版本”。
