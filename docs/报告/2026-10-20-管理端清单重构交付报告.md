## 3. 后端交付

### 3.1 校区上下文

- `AdminCampusContextService`：从 `X-Campus-Id` 解析当前校区；平台管理员判定兼容权限 `platform:all` 与角色 `PLATFORM_ADMIN`；非平台管理员只能停留本校区，越权返回 403，校区不存在返回 400。
- `AdminCampusContextInterceptor`：绑定 `/api/admin/**`，请求结束清理 ThreadLocal，避免线程池串号。
- `GET /api/admin/context` 返回：`userId/displayName/identityType/roles/platformAdmin/campusId/campusName/campuses[]`。
- 已接入校区隔离的管理查询：用户分页/详情、Dashboard 聚合、社区举报与帖子、社区官方号与来源、直投广告与统计、作业分页/创建/关闭、服务申请分页、工单队列、官方通知源/用户/文章/同步。
- 隔离策略是**单校区选择**，不做“全部校区聚合”，避免跨校区误写；平台管理员通过切换器逐校区查看。

### 3.2 写操作审计

- `AdminWriteAuditAspect` 环绕所有 `/api/admin/**` 写方法，成功返回后落审计；审计异常不反向阻断业务。
- 动作优先取 `@Operation.operationId` 转大写下划线；资源由路径归一化（如 `COMMUNITY_DIRECT_ADS`）；资源 ID 优先取路径数字，其次从结果 `adId/userId/id/...` 提取。
- 入参递归脱敏：`password/token/secret/credential/authorization` 等替换，手机号走 `PhoneMasker`；不记录完整敏感值。
- 例外：`/api/admin/system/config` 由 `SystemConfigServiceImpl` 写带 before/after diff 的 `CONFIG_UPDATE`，AOP 跳过以避免双写。
- 已知边界：AOP 只记录**成功**调用；普通写操作的 `beforeJson` 为空，只有配置更新有 before/after diff；审核人字段当前未在广告响应中暴露。

### 3.3 广告主与广告审核

新增表/字段（V68）：

- `community_advertiser`：`id/campus_id/name/contact_name/contact_phone/status/remark/created_at/updated_at/deleted`；按校区隔离、逻辑删除。
- `community_direct_ad` 新增：`advertiser_id/review_status/review_reason/submitted_at/reviewed_by/reviewed_at/effective_status` 等；旧 `ENABLED/DISABLED` 回填为 `APPROVED`，`DRAFT` 保持 `DRAFT`。
- 新权限：`community:ad:review`（审核）、`community:advertiser:manage`（广告主管理），授予平台管理员角色。

管理接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/community/advertisers` | 分页，按当前校区；`keyword/status` |
| POST | `/api/admin/community/advertisers` | 新建广告主 |
| POST | `/api/admin/community/advertisers/{id}` | 编辑 |
| POST | `/api/admin/community/advertisers/{id}/status` | 启用/停用 |
| DELETE | `/api/admin/community/advertisers/{id}` | 逻辑删除 |
| GET | `/api/admin/community/direct-ads` | 分页，支持 `status/reviewStatus/advertiserId/slot/keyword` |
| POST | `/api/admin/community/direct-ads` | 新建，强制 `DRAFT/DRAFT` |
| POST | `/api/admin/community/direct-ads/{id}` | 编辑，仅草稿/驳回可编辑 |
| POST | `/api/admin/community/direct-ads/{id}/submit` | 提交审核，进入 `PENDING`，重复提交幂等 |
| POST | `/api/admin/community/direct-ads/{id}/review` | `APPROVE`/`REJECT`；驳回原因必填；需 `community:ad:review` |
| POST | `/api/admin/community/direct-ads/{id}/status` | 仅 `APPROVED` 且未过期可 `ENABLED`，否则 409 |
| GET | `/api/admin/community/direct-ads/{id}/stats` | 曝光/点击/CTR/可测落地/跳出率/平均停留，可按 N 秒重算 |

状态机：`DRAFT/REJECTED --submit--> PENDING --review--> APPROVED/REJECTED`；仅 `ENABLED + APPROVED + 时间窗内` 进入 App 信息流与广告位。旧的已上线广告被回填为 `APPROVED + ENABLED`，避免演示数据突然消失。

### 3.4 功能开关与 App 广告位

- `GET /api/common/features`（公开；带 Token 时按用户校区）返回 `campusId/flags/generatedAt`；本轮确认 `feature.community_ads=true`。
- `GET /api/app/community/slot-ads?slot=...`（需登录）：按优先级/开始时间返回最多 3 条；每条带新 `clickId`，字段与信息流广告一致；不参与信息流频控。
- 广告事件链路沿用 `IMPRESSION/CLICK/LANDING/DWELL`，`clickId` 贯穿；App 端点击统一走 `AdSlotApi.openLanding/resolveClick`。

### 3.5 隐私与管理端用户手机号

`PhoneMasker.mask`：

- 11 位手机号 → `138****0000`；
- 6 位号码 → `12****56`；
- 其它长度按中间掩码保留首尾；
- null/空白 → null。

`AdminUserSummaryResponse` 对管理端用户列表统一调用；管理端 DTO 不返回明文手机号。广告主联系电话属于投放联系人资料，与用户手机号脱敏边界不同，按广告主管理权限展示。

## 4. 管理端重构

### 4.1 模块结构（无构建链）

```text
src/main/resources/static/admin/
├── index.html                 # vendor → core/api → context → router → registry → pages(defer) → app(module)
├── js/core/
│   ├── api.js                 # 统一客户端、Result 解包、X-Campus-Id、401
│   ├── context.js             # 校区上下文、localStorage、load/setCampus
│   ├── router.js              # 30 路由元数据、权限过滤、页面映射、hash 监听
│   └── registry.js            # 页面注册中心，Proxy 兼容 window.AdminPages
├── js/app.js                  # Campus OS 壳层：登录守卫、顶栏、rail、⌘K、健康、主题
├── js/pages/**                # 30 个页面脚本
└── css/**                     # admin.css / pages.css / campus-os.css 与响应式
```

选择说明：项目部署形态是 Spring Boot 静态资源直出，管理端历史页面全部是全局脚本；本轮把核心层改成原生 ES Module 并保留 `window.AdminApi/AdminPages/AdminApp` 兼容入口，**没有引入 Vite/TypeScript/Node 构建**，降低部署与回滚风险。代价是脚本顺序依赖 HTML 规范（defer 按序执行）和现代浏览器（ES Module/Proxy）。

### 4.2 30 条路由

概览：总览；服务运营：服务目录、服务申请、工单调度、服务评价；社区：社区概览、帖子管理、举报处置、申诉复核、分区管理、话题管理、屏蔽词、官方通知、官方与运营账号、信息流广告、广告主管理；内容与智能：AI 基座、知识库、AI 对话测试、通知公告；用户与组织：用户管理、角色权限、组织架构、字典管理、成就管理；业务运营：作业管理；系统管理：版本发布、审计日志、校区管理、系统配置。

> AI 基座四个页签（模型配置 / 模型列表 / 默认模型 / 测试）已在 2026-10-20 视觉改版中完整落地，含真实 SSE 与暗色适配，详见[科技蓝高密度视觉改版报告 §2.5](2026-10-20-管理端科技蓝高密度视觉改版.md#25-ai-基座四页签重做)。

本轮新增 `community-advertisers`（广告主管理），路由总数 29 → 30。旧文档/旧 smoke 中“29 路由”口径需要以 30 为准。

### 4.3 校区切换器

- 顶栏 `campus-pill` 打开下拉，列出上下文返回的 campuses；当前项标记「当前」，平台管理员可点击其它校区。
- 切换：`AdminContext.setCampus(id)` 写 `localStorage.admin_campus_id` → 记录一次性提示 → `location.reload()`；重载后先 `/api/admin/context`（带新 header）再渲染业务页，页面首个请求即带新 `X-Campus-Id`。
- 实测：`示例大学 → 东校区 → 示例大学` 往返成功，localStorage 与顶栏同步；切到东校区后用户列表从 19 降为 0，证明查询过滤生效。
- 跨校区写入实测：带 `X-Campus-Id=东校区` 创建的广告主「东区打印店」只在东校区列表可见，主校区列表不出现；验证后已逻辑删除。
- 降级：context 加载失败保留既有用户信息并提示，不白屏；缓存校区失效（400/403）自动清缓存后用账号默认校区重试一次。
- 边界：非平台管理员只能看到本校区；切换整页 reload，未保存的表单状态会丢失（产品取舍）。

### 4.5 页面层

- `community-ads.js`：审核状态列/筛选、待审核 KPI、广告主列/筛选；新建/编辑草稿；DRAFT/REJECTED 可编辑+提交审核；PENDING 显示审核；APPROVED 且未过期才显示上架；审核弹层支持通过/驳回（驳回原因必填）；保留原可测/不可测提示与统计弹窗。

## 7. 已知限制与风险

1. **管理端是免构建 SPA**：原生 ESM + 全局 Vue/Element Plus，不使用 Vite/TS；依赖 defer 顺序和现代浏览器（ES Module/Proxy）。旧浏览器不可用。
2. **路由口径 29 → 30**：所有旧文档/旧 smoke 中的 29 需改 30；本报告与 `tools/admin_smoke.py` 已按 30 执行。
3. **审计只记录成功写操作**：失败请求不会留审计；普通写操作无 before JSON，只有配置更新有 diff；`reviewedBy` 在广告响应中未暴露，页面不显示审核人。
4. **Ad review 的旧数据回填**：V68 把旧 `ENABLED/DISABLED` 回填为 `APPROVED`，因此历史广告不会重新走审核；这是兼容取舍，新广告必须走状态机。
5. **广告事件接口未鉴权/未频控**：曝光/点击/落地/停留上报当前不强制登录（便于 WebView/落地页），slot-ads 不参与信息流频控；生产需补签名、限流与反作弊。
6. **SPLASH 只有测试态**：当前后端无 SPLASH 数据，未在真机目视；widget 测试覆盖展示/3 秒自动关闭/跳过/无数据。需要运营配置 SPLASH 广告后再做一次真机验收。
7. **`feature.ai` 未消费**：原因见 §5；`feature.maintenance` 也不在本轮范围。
8. **广告主下拉只取前 50**：广告页/广告主页下拉当前 `pageSize=50`，超过需后端支持不分页或远程搜索。
9. **权限边界只做了平台管理员真机路径**：`community:moderate` 能进广告页但按钮按 `ad:manage/ad:review` 只读，符合“最小权限”前端策略，但需产品确认；有限角色 403/409 文案未用真实低权限账号逐条点验。
10. **校区切换整页 reload**：未保存表单/弹窗状态丢失；只支持单校区查看，不做全校区聚合。
11. **管理端用户手机号本轮 dev 数据为空**：脱敏由 `PhoneMasker` 单测 + `AdminArchitectureIntegrationTest` 覆盖，未在真实有手机号的用户行做 UI 目视；生产数据接入后应补一次页面核验。
12. **APK 是 debug/arm64 验收包**：非 release 签名；连接 `10.0.2.2:9000`，真机需改局域网地址后重建。
13. **广告计划未单独建表**：当前每条直投广告记录即一个投放单元（含排期/优先级/广告位/状态），广告主可关联多条广告；没有“广告计划 → 多素材/多广告位”的 campaign 聚合层。若后续需要计划/订单/素材分层，应在现有表之上增加 campaign/order 表，而不是改直投广告状态机。
