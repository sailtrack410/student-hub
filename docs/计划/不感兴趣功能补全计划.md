# 「不感兴趣」功能补全计划（P1.3 后续）

> 基线：2026-10-30 已落地最小诚实版（提交见 git log，`_hideFromFeed`）。
> 当前置为：详情页菜单「不感兴趣（在信息流隐藏此帖）」→ 调 `CommunityInteractionStore.setHidden(postId, true)`，
> 仅在**本机信息流**过滤该帖；提示语如实标注「仅本机，不影响分享与主页查看」。
> 本计划为独立后续任务清单，与当前真实性修复批次解耦。

## 现状边界（为什么先这样落地）

- 隐藏仅作用于首页/分区信息流（`CommunityFeedController._visible` 过滤）。
- 通过**分享、作者主页、搜索**等入口仍可正常进入该帖子查看——本地隐藏不影响任何服务端数据。
- 隐藏数据存 SharedPreferences，**换设备/重装即丢失**。
- App 当前无深链（无 scheme/intent-filter），分享是纯文本复制，不存在 URL 直达场景。
- 后端无个性化推荐系统：「推荐」tab 实际是 `sort=HOT`（点赞→评论→时间全站倒排），帖子实体无权重字段。

## 待补全任务清单（按优先级）

### 1. 服务端持久化隐藏列表（与 P1.5 收藏/隐藏同步合并做）
- 新表 `community_user_hide`（user_id + post_id + created_at，唯一键防重）。
- App 端 `setHidden` 成功后异步上报服务端；拉取信息流时服务端直接过滤或客户端合并过滤。
- 换设备登录后隐藏列表按账号恢复。
- 已删除/下架帖子的隐藏记录提供失效状态与清理操作（与收藏管理同口径）。
- 归属模块：preference 或 community，建议与「我的收藏/已隐藏管理页」（P1.5）同一批设计。

### 2. 「我的收藏 / 已隐藏」管理入口
- 个人中心新增两个列表页，支持取消收藏、取消隐藏。
- 服务端同步落地后，管理页数据源切服务端。
- 依赖任务 1。

### 3. 屏蔽作者（维度升级，价值最大）
- 新表 `community_user_block`（user_id + blocked_author_id + created_at）。
- 服务端 `pagePosts` / 作者主页接口对已屏蔽作者 `notIn(authorId)` 过滤。
- 详情页「不感兴趣」弹二级选择：不看此帖 / 不看此作者。
- 客户端屏蔽作者后本地即时过滤 + 刷新；作者主页提示「你已屏蔽该作者」。
- 边界：被屏蔽作者的评论是否也隐藏（建议：列表折叠显示「已屏蔽作者的评论」，可展开）。

### 4. 深链入口的隐藏兜底（做深链/分享落地页时一并）
- 将来加 scheme / universal link 直达帖子时，落地入口需查一次 hidden store，
  已隐藏帖子是否拦截由产品定（建议：仍允许查看，只是不进信息流，保持与现在一致的语义）。

### 5. 不做项（明确排除，避免范围蔓延）
- 分区维度「不感兴趣」：分区本身有 tab 切换，用户不看就不会点，伪需求。
- 话题维度负向过滤：topics 是 JSON 字符串字段，负向过滤成本高收益低。
- 帖子推荐权重/个性化推荐系统：需要特征/召回/排序全链路，与「真实性与完整性优先」主线冲突，另立项再议。

## 验收口径（每个任务通用）
- 界面提示与实际行为一致（不许出现做不到的承诺文案）。
- 写操作失败必须如实报错，不允许假成功。
- 撤销路径完整可用。
- 回归测试沿用 `community_hide_truthfulness_test.dart` 模式扩展。
