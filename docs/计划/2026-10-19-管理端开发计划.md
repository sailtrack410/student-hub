## 一、目标与原则

### 1.1 目标

1. 管理端从“页面集合”升级为**校园运营控制台**：待办、治理、配置、数据、审计形成闭环。
2. 当前所有可配置项都有**可视页面或开关**，不再依赖直接改数据库/环境变量。
3. 页面覆盖：**真实功能、空态、错误态、权限、审计、响应式**六个维度。
4. 架构可维护：新页面用 Vite + Vue 3 SFC + TypeScript，旧页面按批次迁移，不做一次性重写。
5. 与 App 共享品牌 token 和设计语言，但管理端保持桌面运营效率优先。

### 1.2 三条硬约束

- **不把密钥搬到网页明文**：API Key、AppSecret、DB 密码等只显示“已配置/未配置”、掩码后四位、连通性测试；原文仍由环境变量/Secret 管理。
- **每一个写操作必须有权限、校验、审计**；不能只有前端按钮。
- **每个页面必须有 loading / empty / error / forbidden 四态**；不能只做“正常数据截图”。

### 1.3 配置来源分级

| 级别 | 示例 | 管理端呈现 | 保存方式 |
|---|---|---|---|
| `DB-RUNTIME` | 功能开关、公告、分区、SLA、模板、推荐位 | 可视化表单/开关，实时生效 | `sys_config` / 业务表 |
| `DB-SECRET` | AI API Key、微信/QQ Secret、MinIO Secret | 掩码展示 + 测试连接 + 更新 | 加密存储或 Secret 引用，只回显状态 |
| `ENV-READONLY` | DB URL、Redis Host、会话存储类型、Flyway | 状态页只读展示 + 部署提示 | 环境变量/部署平台，不提供网页改值 |
| `DB-ENTITY` | 服务目录、角色、组织、用户、勋章、字典、版本 | 标准 CRUD 页面 | 业务表 |
| `CODE/INFRA` | 数据库/Redis 健康、磁盘、任务执行 | 只读状态页/手动触发 | 只读 + 运行操作 |

> 结论：**所有配置都要“可见、可判断、可操作或明确只读原因”**，但不等于所有密钥都能在网页修改。

### 7.1 工程化

- 迁移 **Vite + Vue 3 SFC + TypeScript**，Element Plus 保留；

- 暗色模式纳入验收；
- 所有配置页有“保存/重置/恢复默认/变更记录”。

### 7.3 页面模板（每个配置页必须满足）

```text
保存反馈 + 错误定位

```
