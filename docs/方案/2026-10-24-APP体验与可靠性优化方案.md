# APP 体验与可靠性优化方案

日期：2026-10-24。实施对象：当前工作树中的 Flutter APP（`app/`）。

配套执行表：[APP 优化执行清单](../计划/2026-10-24-APP优化执行清单.md)。本方案以当前源码评审为依据；旧版功能补齐文档中的演示数据、开发登录等结论不直接沿用。

## 1. 目标与现有基础

保留浅底、白卡、宝蓝主色、青绿 AI 和“首页／社区／绵宝 AI／消息／我的”五栏导航。已有 QQ 与账号登录、课表成绩、办事工单、社区私信、AI 流式消息与来源、设备管理、隐私偏好、更新检查和功能开关继续复用。

优化顺序是：真实数据与可靠反馈 → 核心任务层级 → 设备适配与可读性 → 状态与组件统一 → 模块维护成本。一次完成若干可验证的小项，完成后立即更新执行清单；没有完成验证的项目保持未勾选。

## 2. 数据与状态的基本要求

1. AI 服务出错时显示失败、重试及真实业务入口；课程、绩点、排名、政策时限等不得用本地固定答案冒充查询结果。已经收到的流式片段在中断后保留，并明确标识未完成。
2. 新对话必须丢弃旧会话 ID；重置本地页面与删除服务端历史分别表述。旧请求返回后不得写入新对话。
3. 网络不可用与认证失效分别处理。只有明确认证失败才清除登录态；弱网保留同一账号的最近会话，不能恢复其他账号的资料。
4. 收藏、点赞、关注、清缓存等操作的反馈必须对应实际结果。乐观更新需要请求期间防重和失败恢复；本机保存必须说明保存位置。
5. 未填写学籍、未获得勋章、尚未同步的数据分别使用真实空态，不补造个人经历。

## 3. 页面调整建议

### 首页

内容顺序调整为问候与消息 → 今日课程与待办 → 常用服务 → 校园动态。广告和活动后置，并保留推广标识。课表和待办优先显示“下一步能做什么”，避免一个大面积推广卡占据首屏。

常用服务后续采用短名称和推荐／用户固定顺序；后台目录的自然顺序不直接视作用户偏好。首页接口分区域管理状态，课程成功、动态失败时仍保留课程内容。

底栏以系统安全区作为底部留白，使用最小高度而非固定整栏高度。触控目标至少 48dp；图标、文字、未读状态具有语义描述，读屏能区分已选中项目。

### AI 助手

保留附件、Markdown 和引用来源。失败气泡包含重试、查看课表、查看成绩等真实入口。重试同一问题不重复追加用户气泡；带附件重试保留附件 ID。发送与流式接收期间禁止重复提交，但不得因为收到首个片段就允许另一次并发发送。

新对话的确认文案明确“开始新对话，服务端历史不因此删除”。中断流保留部分内容并结束输出状态。服务端动作后续改为类型化协议，避免单纯依靠按钮文案猜路由。流式和普通接口的回退／重试还应共用请求 ID 与服务端唯一幂等键，防止服务端已接收但客户端未收到片段时重复记录和消耗模型配额；本轮 UI 不重复追加用户气泡不等于服务端已经幂等。

### 设置与个人中心

设置按“账号与绑定／通知／隐私与展示／通用与关于”组织。账号密码入口复用现有账号管理，设备入口不固定展示 iPhone。系统推送授权与站内消息偏好分开说明，避免多个开关表达同一个概念。

缓存清理仅处理可重新下载的缓存，不删除登录凭证、用户偏好和办理材料。只有实际清理成功后才显示成功；准确大小显示需要单独完成统计。

个人中心学籍缺失时提示完善资料；已获徽章只来自接口，未获得的徽章在独立解锁区展示。我的申请、学业入口、认证状态应先于成长与社交统计。

### 社区

点赞与关注按帖子 ID／作者 ID 跟踪，不能在网络返回后依赖旧列表索引。关注状态需要同步同一作者的所有可见帖子。操作失败恢复状态并允许重试，提交期间防止反复切换造成竞态。

收藏优先接服务端；如当前后端没有接口，可先完成按账号隔离的本机收藏，并明确“保存在本机”，首页与详情页共用相同记录。详情及作者页的点赞／关注需要分别验收，首页修复不代表其他入口已经完成。不感兴趣如果没有推荐反馈接口，只能表述为隐藏当前内容，不能承诺减少未来同类推荐。

### 登录与通用适配

登录后续改为 SafeArea、约束布局和可滚动内容，避免绝对定位受键盘、小屏与系统字号影响。360／390／430dp 宽、1.0／1.3／1.5 倍字号、Android 手势／三键导航作为主要矩阵，320dp 用作边界检查。

## 4. 视觉规范

| 对象 | 建议 | 验收重点 |
|---|---|---|
| 正文 | 14–16sp，行高 1.4–1.6 | 不截断关键信息 |
| 辅助文字 | 12–13sp | 普通文字对比度至少 4.5:1 |
| 分区标题 | 18–22sp，按层级使用字重 | 不以多种高饱和色竞争 |
| 触控目标 | 至少 48dp | 图标视觉尺寸与点击面积分别设计 |
| 间距 | 4／8／12／16／20／24 | 同级卡片保持一致 |
| 颜色 | 蓝色主操作、绿色 AI、语义状态色 | 颜色不能作为唯一状态提示 |
| 卡片 | 统一圆角与细边框，少量阴影 | 保持当前风格，避免叠加装饰 |

`#94A3B8` 在白底上的对比度约 2.56:1，不适合小字号关键信息。逐步由 `TextTheme` 和公共按钮／表单／状态组件承接规范；只增加主题声明并不能证明所有现有页面已经适配。

深色主题、跟随系统、字号设置与减少动画应在全页面覆盖和持久化完成后再开放，不放置无效开关。

## 5. APP 代码结构

继续使用当前 API 层和模型，逐个 feature 拆分页面、状态控制器、仓储及卡片组件。优先处理超过千行的首页、社区、AI 页面。集中网络错误、请求取消、分页、刷新和导航的语义，避免为改架构而整体重写。

离线数据必须按账号隔离，包含时间戳和来源；切换账号不能看到上一个账号的缓存。先完成会话恢复，再扩展最近课表等业务缓存。

## 6. 发布页与后端的后续配合

本轮先实施 APP。发布页与架构保留以下独立后续工作，详见执行表中的 W／S 项：

- 发布页使用稳定下载地址与同一版本记录的元数据；区分接口失败和没有发布版；二维码指向稳定落地页，微信／Android／iOS 分别给实际可用路径。
- 发布页更新登录文案、服务状态和演示截图；内容默认可见，补图库键盘和触控交互。
- 管理端渐进采用路由加载、公共表格／筛选／错误面板，逐页迁移 SFC／TypeScript／Vite。
- 后端保留模块化单体；优先修复版本发布事务和不可变包路径、有界 AI 线程池与取消、通知 outbox、原子任务抢占、可恢复 RAG 索引。
- 多实例部署前再统一验证码 Redis 与 WebSocket 路由，逐步收紧领域间 Mapper 依赖。

## 7. 实施、验证与回退

第一批处理 AI 失真兜底、会话恢复、设置真实反馈、社区状态一致性、个人资料空态、首页排序与底部安全区。每个子项都在执行表记录实现文件和验证结果。

在修改前对当前 APP 源码和测试保存 SHA-256 与副本。基线及修改后运行 Flutter 测试和静态分析；对新增关键状态分支补充行为回归。UI 调整通过组件测试验证尺寸与状态，真机观感和系统交互单独标记待验收。

交付保留本批差异、验证记录和可执行回退脚本；回退脚本只恢复本批实际修改文件，不使用 Git 重置覆盖当前已有工作。先在另一个副本验证回退，再保留工作树中的修改供继续迭代。
