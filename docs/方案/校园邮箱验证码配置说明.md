# 校园邮箱验证码配置说明（2026-10-20）

> 适用范围：注册、找回密码、绑定校园邮箱时的邮箱验证码。
> 代码位置：`integration/mail/SmtpEmailCodeSender`、`integration/mail/MailConfig`、
> `modules/identity/service/impl/IdentityAuthServiceImpl#sendEmailCode`。
> 关键原则：**生产环境未配置 SMTP 时必须明确失败，不能伪报“验证码已发送”。**

## 1. 行为矩阵

| 环境 | SMTP 已配置 | 行为 |
|---|---|---|
| dev / test | 否 | 不真实发信，接口响应返回 `devCode`，提示“开发环境未配置邮件服务，验证码已直接返回” |
| dev / test | 是 | 真实发信；同时允许响应返回 `devCode`（`MAIL_DEV_RETURN_CODE=true` 时） |
| prod | 是 | 真实发信，响应 `devCode=null`，提示“验证码已发送至邮箱，请查收” |
| prod | 否 | 返回 `AUTH_503_03 邮箱服务尚未配置`，不存储验证码、不伪报成功 |
| 任意 | 发信异常 | 返回 `AUTH_502_01 验证码发送失败`，不存储验证码 |

`devCode` 是否可见同时受两个条件限制：`MAIL_DEV_RETURN_CODE=true` **且**当前 Spring Profile 为 `dev`/`test`。生产 profile 即使误配 `MAIL_DEV_RETURN_CODE=true` 也不会返回验证码。

验证码为 6 位数字，10 分钟有效，按“用途 + 邮箱”隔离；验证码不写日志。

## 2. 配置入口

从 2026-10-20 起，SMTP 配置可以在管理端「系统配置 → 运行配置 → 邮箱 SMTP」直接修改并热更新，无需重启：

- 首次启动仍从环境变量读取非空值，写入空白的 `sys_config` 种子行；
- 管理端保存的值写入数据库并立即刷新 `JavaMailSender`，优先级高于环境变量；
- `SMTP 密码` 使用 `CONFIG_SECRET_KEY` 派生的 AES-256-GCM 密钥加密落库，页面/API 不回显；
- 管理员显式清空某项后不会回退环境变量；
- 外部集成页可对当前 SMTP 配置做真实连接测试，失败只返回脱敏摘要。

部署时可继续用下面的环境变量作为初始值（真实值禁止提交 Git）。

## 2.1 环境变量

在部署平台或未跟踪的 `.env` 中配置（真实值禁止提交 Git）：

```bash
MAIL_ENABLED=true
MAIL_HOST=smtp.example.com
MAIL_PORT=465
MAIL_USERNAME=no-reply@example.com
MAIL_PASSWORD=change-me
MAIL_FROM=no-reply@example.com
MAIL_FROM_NAME=绵城一码通
MAIL_SSL_ENABLED=true
MAIL_STARTTLS_ENABLED=false
MAIL_CONNECT_TIMEOUT_MS=5000
MAIL_READ_TIMEOUT_MS=5000
MAIL_WRITE_TIMEOUT_MS=5000
# 只有 dev/test profile 生效；生产不返回验证码
MAIL_DEV_RETURN_CODE=true
```

常见端口组合：

| 端口 | `MAIL_SSL_ENABLED` | `MAIL_STARTTLS_ENABLED` |
|---|---|---|
| 465（SMTPS） | `true` | `false` |
| 587（Submission） | `false` | `true` |
| 25（内网中继） | 按邮件服务器要求 | 按邮件服务器要求 |

- `MAIL_USERNAME` 留空时不启用 SMTP AUTH，适用于仅允许内网 IP 的中继。
- `MAIL_FROM` 留空时回退使用 `MAIL_USERNAME`；`MAIL_FROM_NAME` 为收件人看到的发件人显示名。
- QQ 邮箱、163 邮箱等通常要求使用“授权码”而不是登录密码，且发件地址需与账号一致。

## 3. 启动与验证

```bash
# 本地开发：不配置 SMTP，接口直接返回 devCode，便于注册/找回联调
MAIL_ENABLED=false ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev

# 生产/预发：配置 SMTP 后验证真实收信
MAIL_ENABLED=true MAIL_HOST=smtp.example.com MAIL_PORT=465 \
MAIL_USERNAME=no-reply@example.com MAIL_PASSWORD='***' \
MAIL_FROM=no-reply@example.com \
./mvnw spring-boot:run -Dspring-boot.run.profiles=prod
```

验收步骤：

```bash
# 1) 请求验证码（生产响应不应包含 devCode）
curl -s -X POST http://127.0.0.1:9000/api/common/auth/email-code \
  -H 'Content-Type: application/json' \
  -d '{"email":"student@stu.mycc.edu.cn","purpose":"REGISTER"}'

# 2) 检查目标邮箱收到邮件，邮件标题为“【绵城一码通】注册账号验证码”
# 3) 使用收到的验证码调用 /api/common/auth/register
```

生产未配置 SMTP 的预期响应：

```json
{
  "success": false,
  "code": "AUTH_503_03",
  "message": "邮箱服务尚未配置，请联系管理员",
  "data": null
}
```

## 4. 安全与运维注意事项

- 验证码只存服务端内存（`EMAIL_CODES`），重启即失效；多实例部署前应迁移到 Redis，并增加发送频率限制，避免被刷邮件。
- 日志只记录脱敏邮箱（如 `s***@example.com`）、用途和失败原因，不记录验证码、SMTP 密码。
- SMTP 密码在管理端保存时使用 AES-256-GCM 加密落库；`CONFIG_SECRET_KEY` 必须通过环境变量/密钥服务注入，`.env` 已在 `.gitignore` 中，不得提交。
- 生产建议使用独立发信子域并配置 SPF、DKIM、DMARC，避免验证码进入垃圾箱。
- 发送失败会向客户端返回 502，不会把“未配置/发送失败”伪装成成功；前端（`email_binding_page.dart`、注册/找回页）直接展示后端 message。
