## 一、账号类型

社区账号分四类，统一挂在 `sys_user` 之上，通过 `community_account` 扩展：

| 类型 | 编码 | 说明 | 谁能发帖 | 标识 |
|---|---|---|---|---|
| 普通用户 | `NORMAL` | 学生/教师/后勤等自然用户 | 本人 | 等级/身份 |
| 官方自动号 | `OFFICIAL_AUTO` | 学校官网抓取内容，由 `official_feed_source` 绑定 | 抓取任务/管理员手动补发 | 官方 + 来源 |
| 官方运营号 | `OFFICIAL_HUMAN` | 部门/学院真人运营，可多人协作 | 绑定运营人 | 官方 + 部门/头衔 |
| 广告服务号 | `AD_SERVICE` | 校园商家/合作方推广内容 | 广告运营/审核后发布 | 推广 + 广告主 |

### 1.1 官方自动号

- 绑定一个或多个 `official_feed_source`；
- 内容由定时任务抓取、解析、发布；
- 展示“官方 · 来源”（如“官方 · 教务处”）；
- 同步失败进入 admin 异常队列，可手动重试/补发；
- 不可被普通用户冒用，不允许普通发帖入口创建。

### 1.2 官方运营号

- 一个账号可绑定多个运营人（`community_account_operator`）；
- 运营人可代发、回复、置顶，但每条内容写入操作审计；
- 支持部门/学院/学生组织等官方主体；
- 展示“官方 · 头衔”，不显示等级；
- 停用/换人时保留历史内容与审计。

### 1.3 广告服务号

- 广告主（`advertiser`）绑定一个或多个广告账号；
- 广告内容走“广告订单/投放计划 → 素材 → 审核 → 排期 → 发布”；
- 展示“推广 / 广告主”，**不得伪装成官方**；
- 支持频控、定向分区/校区、起止时间、预算（P2）；
- 统计曝光/点击/互动，支持导出。

## 二、数据模型

### 2.1 `community_account`

| 字段 | 说明 |
|---|---|
| id | 主键 |
| user_id | 关联 `sys_user` |
| account_type | NORMAL/OFFICIAL_AUTO/OFFICIAL_HUMAN/AD_SERVICE |
| display_name | 社区展示名 |
| badge_text | 展示标识（如“教务处”） |
| owner_org_id | 归属组织 |
| verification_status | PENDING/APPROVED/REJECTED/DISABLED |
| official_source_id | 官方自动号绑定来源，可空 |
| advertiser_id | 广告服务号绑定广告主，可空 |
| description | 账号简介 |
| status | ENABLED/DISABLED |
| created/updated/deleted/version | 审计字段 |

唯一约束：`user_id`；`official_source_id` 一个来源只能绑定一个自动号。

### 2.2 `community_account_operator`

`account_id + user_id + role`：官方运营号/广告号的运营人；`role = OWNER/OPERATOR`。

### 2.3 `advertiser`

| 字段 | 说明 |
|---|---|
| id | 主键 |
| name | 广告主名称 |
| contact_name/contact_phone/contact_email | 联系人 |
| campus_id | 校区 |
| industry/license_no | 行业/资质 |
| status | PENDING/APPROVED/REJECTED/DISABLED |
| created/updated/deleted/version | 审计字段 |

### 2.4 `ad_campaign`

| 字段 | 说明 |
|---|---|
| id | 主键 |
| advertiser_id | 广告主 |
| name | 投放计划名 |
| title/content/images | 帖子素材 |
| section_id | 投放分区 |
| start_at/end_at | 起止 |
| status | DRAFT/PENDING_REVIEW/APPROVED/REJECTED/ACTIVE/PAUSED/ENDED |
| sponsored_label | 展示文案（推广/广告） |
| budget_cents | 预算，P2 |
| created/updated/deleted/version | 审计字段 |

### 2.5 `community_post` 扩展

| 字段 | 说明 |
|---|---|
| post_kind | NORMAL/OFFICIAL/SPONSORED |
| account_id | 发布账号 |
| campaign_id | 关联广告计划，可空 |
| sponsored_label | 展示“推广/广告” |
| source_type/source_id | 官网来源/手工/广告 |

现有帖子迁移默认 `post_kind=NORMAL`，历史官方号按 `sys_user.official` 回填 `OFFICIAL`。

### 2.6 权限

| 权限码 | 用途 |
|---|---|
| `community:account:manage` | 账号创建/审核/停用/运营人绑定 |
| `community:official:operate` | 官方运营号代发/回复/置顶 |
| `community:ad:manage` | 广告主/广告计划/素材 |
| `community:ad:review` | 广告审核/驳回/下线 |
| `community:ad:stats` | 曝光/点击/报表导出 |

## 三、管理端页面

### 3.1 社区账号管理 `#/community-accounts`

- 列表：账号、类型、归属组织、运营人、绑定来源/广告主、状态、最近发布、操作；
- 筛选：类型、组织、验证状态、账号状态；
- 操作：新建官方号/广告号、审核、绑定运营人、绑定官网来源、停用、查看内容；
- 详情 Inspector：基本信息、运营人、绑定关系、发布记录、审计。

### 3.2 官方号运营 `#/community-official-operate`

- 官方自动号：来源同步状态、最近抓取、失败重试、手动补发；
- 官方运营号：内容列表、代发、置顶、回复、发布日历；
- 审计：谁操作了哪个官方号。

### 3.3 广告服务 `#/community-ads`

四个页签：

1. **广告主**：申请、资质、审核、联系人、状态；
2. **投放计划**：素材、分区、起止、状态、审核；
3. **审核队列**：待审/驳回/上线/下线，带预览与风险提示；
4. **数据**：曝光、点击、互动、CTR、消耗（P2 预算）。

操作：
- 新建广告主/计划；
- 提交审核/通过/驳回（原因）；
- 暂停/恢复/结束；
- 预览帖子（App 样式）；
- 导出数据。

### 3.4 帖子管理增强

- 列表展示 `post_kind`、账号类型、广告主/来源；
- 官方/广告内容不能与普通内容混淆；
- 官方自动内容可跳转来源配置；
- 广告内容可跳转计划详情；
- 支持按类型筛选与批量下线。

## 八、官方直投广告（补充）

### 8.1 定义

**官方直投广告**由平台/学校直接创建，不需要真人运营账号，也不发普通社区帖子。运营人员只填写广告字段、素材、跳转链接和投放时间，审核通过后作为“广告位”展示，用户点击直接跳转链接。

它与已有类型的区别：

| 类型 | 是否发社区帖子 | 是否需运营人 | 是否可评论 | 点击行为 |
|---|---|---|---|---|
| 官方自动号 | 是 | 否（抓取任务） | 可配置 | 阅读原文 |
| 官方运营号 | 是 | 是（多运营人） | 可配置 | 进入帖子 |
| 广告服务号（商家） | 是 | 是（广告主/运营） | 可关闭 | 进入帖子/跳转 |
| **官方直投广告** | **否（广告位）** | **否** | **否** | **直接跳转链接** |

### 8.2 字段

#### 基本信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 广告名称 | 是 | 仅后台使用，如“2026 春季招生咨询” |
| 广告主/来源名称 | 是 | App 展示，如“绵阳城市学院招生办” |
| 投放校区 | 是 | 单校区或多校区 |
| 广告位 | 是 | 社区信息流 / 首页焦点图 / 启动弹窗 / 服务大厅横幅 |
| 投放分区 | 否 | 信息流广告可选社区分区 |
| 开始/结束时间 | 是 | 服务端校验 |
| 状态 | 是 | DRAFT/PENDING_REVIEW/APPROVED/ACTIVE/PAUSED/ENDED |
| 优先级/权重 | 否 | 多个广告的排序 |
| 频次上限 | 否 | 单用户每日/每次启动展示次数 |
| 展示标识 | 是 | “推广”/“广告”/“官方推广”，默认“推广” |

#### 素材

| 字段 | 必填 | 说明 |
|---|---|---|
| 标题 | 是 | 信息流广告主标题 |
| 文案 | 否 | 1–2 行摘要 |
| 图片/视频 | 是 | 信息流 1 张；Banner 按广告位尺寸 |
| CTA 文案 | 否 | “了解详情”“立即报名”“去官网”等 |

#### 跳转

| 字段 | 必填 | 说明 |
|---|---|---|
| 跳转类型 | 是 | EXTERNAL_URL / DEEPLINK / APP_PAGE |
| 跳转地址 | 是 | https 或白名单 deeplink |
| 兜底地址 | 否 | deeplink 失败时打开 |
| 打开方式 | 否 | 内置浏览器/系统浏览器 |
| 渠道参数 | 否 | utm_source/utm_campaign 等自动拼接 |

#### 审核与统计

- 审核状态、审核人、审核意见、审核时间；
- 曝光、点击、去重点击、CTR；
- 按广告位/校区/时间段统计；
- 导出。

### 8.3 创建流程

```text
新建官方直投广告
→ 填写字段/上传素材/配置跳转
→ 预览（信息流/Banner 效果）
→ 链接安全校验（HTTPS、域名白名单、可达性）
→ 提交审核
→ 通过/驳回
→ 定时/立即上线
→ 曝光/点击统计
→ 暂停/结束
```

**不需要**绑定官方运营号、不需要绑定广告主账号、不需要运营人；平台管理员即可创建。

### 8.4 校验规则

- 只允许 `https://`；禁止 `javascript:`、`data:`、`file:`；
- 外链域名白名单（学校域名 + 已审核域名）；
- deeplink 只允许 App 注册的 scheme/host；
- 链接必须可访问（HEAD/GET 校验，失败给警告）；
- 结束时间必须晚于开始时间；
- 上线前必须有素材、标题、跳转地址、展示标识；
- 同一广告位/同一用户频控由服务端控制；
- 广告不得使用“官方”“学校”等标识误导，展示标识必须清楚；
- 广告位关闭评论；不进入自然热门榜。

### 8.5 管理端页面

在 `#/community-ads` 下新增 **官方直投** 页签：

- 列表：广告名称、广告主名称、广告位、校区、时间、状态、曝光、点击、CTR、操作；
- 新建/编辑抽屉：
  - 基本字段；
  - 素材上传与预览；
  - 跳转配置与链接校验；
  - 投放时间/频控/权重；
  - 保存草稿/提交审核/上线/暂停/结束；
- 审核队列：待审、驳回原因；
- 数据：按广告位/校区/日期筛选，导出。

不出现“运营人”“社区账号”字段。

### 8.6 App 展示

- 信息流：作为一条带“推广”标识的广告卡，不显示评论区；
- Banner：顶部/服务大厅横幅，点击跳转；
- 启动弹窗：可关闭，频控；
- 点击后：
  - `EXTERNAL_URL`：系统浏览器/内置浏览器打开；
  - `DEEPLINK`：App 内跳转，失败打开兜底 URL；
  - `APP_PAGE`：跳转 App 内指定页；
- 曝光/点击上报服务端，用于统计和频控。

## 九、官方直投广告进入信息流与跳出率统计（补充）

### 9.1 信息流投放

官方直投广告作为**信息流广告卡**插入社区推荐/最新流，不是普通帖子：

- 支持广告位：`FEED`（信息流）、`BANNER`、`SPLASH`、`SERVICE_HALL`；
- 信息流默认插入节奏：每 N 条自然内容最多 1 条广告，N 可配置（默认 8）；
- 支持按校区、分区、用户角色/身份定向；
- 单用户单日/单次会话展示上限；
- 不参与自然热度排序，不进入“热门/推荐”自然榜；
- 展示“推广”标识、广告主名称、CTA；
- 无评论区，不显示点赞/收藏等社区互动；点击直接跳转。

> 信息流广告由后端组装：先查自然内容，再由广告投放服务按位置插入；客户端只负责渲染并上报曝光。禁止把广告伪装成普通帖子。

### 9.2 点击与落地

点击链路：

```text
曝光 impression
→ 点击 click（生成 click_id）
→ 打开落地页/App 页面
→ landing_start（页面开始加载）
→ landing_loaded（页面可交互）
→ landing_exit（关闭/返回/切走/超时）
→ 结算 dwell_ms / bounced
```

跳转类型：

| 类型 | 能否测量跳出率 | 说明 |
|---|---|---|
| `IN_APP_WEBVIEW` | ✅ | App 内置 WebView，注入桥接，能测页面加载与停留 |
| `APP_PAGE` | ✅ | App 内路由，能测进入/退出 |
| `EXTERNAL_BROWSER` | ❌ | 系统浏览器，无法读取第三方页面行为，只能记录点击 |
| `DEEPLINK` | ❌ / 部分 | 跳出 App 到第三方，无法读取第三方页面；只能记录点击/回前台 |

**不能用外部浏览器/第三方 App 的点击伪造跳出率**；后台报表需把“可测落地”和“不可测点击”分开。

### 9.3 跳出率定义

- **可测落地点击**：点击后成功打开 `IN_APP_WEBVIEW` 或 `APP_PAGE`，且收到 `landing_loaded` 的点击；
- **跳出**：从 `landing_loaded` 起，用户在 **N 秒内**关闭/返回/切走/进入后台；
- **跳出率** = `N 秒内跳出数 / 可测落地点击数`；
- **平均停留** = `sum(dwell_ms) / 可测落地点击数`；
- N 按广告可配置（默认 5 秒，建议 3/5/8/10 秒）；
- 原始 `dwell_ms` 必须入库，后台可按不同 N 重新计算，不把 N 写死；
- 外部浏览器/deeplink 点击单列为“不可测点击”，不进入跳出率分母。

### 9.4 数据模型补充

`ad_campaign` 增加：

- `feed_interval`：信息流插入间隔（默认 8）
- `daily_impression_cap`：单用户单日曝光上限
- `session_impression_cap`：单次会话曝光上限
- `bounce_threshold_seconds`：N，默认 5
- `cta_text`、`sponsored_label`
- `link_type`：IN_APP_WEBVIEW / APP_PAGE / EXTERNAL_BROWSER / DEEPLINK
- `landing_url`、`fallback_url`

新增 `ad_event`：

| 字段 | 说明 |
|---|---|
| id | 主键 |
| ad_id / campaign_id | 广告 |
| click_id | 点击链路 ID |
| user_id | 用户 |
| event_type | IMPRESSION/CLICK/LANDING_START/LANDING_LOADED/LANDING_EXIT |
| placement | FEED/BANNER/... |
| occurred_at | 时间 |
| dwell_ms | 停留毫秒，landing_exit 时写入 |
| bounced | 是否在 N 秒内跳出 |
| platform/device | 平台/设备 |
| landing_type | WebView/AppPage/External/Deeplink |
| trace_id | 链路追踪 |

索引：`(ad_id, event_type, occurred_at)`、`(click_id)`、`(user_id, occurred_at)`。

### 9.5 上报接口（规划）

```text
POST /api/app/community/direct-ads/{id}/impression
POST /api/app/community/direct-ads/{id}/click
POST /api/app/community/direct-ads/landing/start
POST /api/app/community/direct-ads/landing/loaded
POST /api/app/community/direct-ads/landing/exit
```

- `click` 返回 `clickId` 和跳转配置；
- `exit` 上报 `dwellMs`，服务端按广告 N 计算 `bounced`；
- 服务端需要幂等：同一 `eventId` 只记一次；
- 防刷：同一用户/设备短时间重复点击去重，异常流量标记。
- App 内置 WebView 的页面加载/关闭事件通过桥接上报；第三方页面无法读取时标记 `unmeasurable`。

### 9.6 管理端展示

`#/community-ads` → 官方直投：

- 列表增加：曝光、点击、CTR、可测落地、**N 秒跳出率**、平均停留；
- 详情：按时间/校区/广告位趋势、跳出率分布、链接类型拆分；
- 支持切换 N（3/5/8/10 秒）重算；
- 导出原始事件（脱敏）；
- 外部浏览器/Deeplink 点击单独显示“不可测”，不混入跳出率。

### 9.7 App 端点击体验

- 信息流广告卡点击后：
  - `IN_APP_WEBVIEW`：App 内打开，顶部显示广告主和关闭；页面加载完成上报 `landing_loaded`；关闭/返回上报 `landing_exit`；
  - `APP_PAGE`：路由进入/退出上报；
  - `EXTERNAL_BROWSER`：打开系统浏览器，仅上报点击；
  - `DEEPLINK`：尝试跳转，失败打开兜底页，仅上报点击/不可测；
- 关闭按钮始终可见；
- 落地页无可测能力时后台显示“不可测”，不能显示 0% 跳出率误导。

## 十、实现口径（2026-10-20 管理端清单重构后）

> 本节为**实际落地契约**，用于校正 §八、§九 中早期规划字段/路径；以本节与源码为准。旧字段名（如 `PENDING_REVIEW/ACTIVE/PAUSED`、`placement`、`GET /api/app/community/direct-ads?placement=`）不再使用。

### 10.1 广告位与状态

- 广告位：`FEED`、`BANNER`、`SPLASH`、`SERVICE_HALL`。
- 投放状态：`DRAFT`、`ENABLED`、`DISABLED`。
- 审核状态：`DRAFT`、`PENDING`、`APPROVED`、`REJECTED`。
- 落地类型：`IN_APP_WEBVIEW`、`APP_PAGE`、`EXTERNAL_BROWSER`、`DEEPLINK`。
- 状态机：`DRAFT/REJECTED --submit--> PENDING --review--> APPROVED/REJECTED`；仅 `APPROVED` 可 `ENABLED`；App 只消费 `ENABLED + APPROVED + 时间窗内`。`effectiveStatus` 由后端按时间窗与状态计算后返回。

### 10.2 实际接口

```text
GET    /api/admin/community/direct-ads?status=&reviewStatus=&advertiserId=&slot=&keyword=&pageNum=&pageSize=
GET    /api/admin/community/direct-ads/{adId}
POST   /api/admin/community/direct-ads
POST   /api/admin/community/direct-ads/{adId}
POST   /api/admin/community/direct-ads/{adId}/status       {status: ENABLED|DISABLED|DRAFT}
POST   /api/admin/community/direct-ads/{adId}/submit       无 body，幂等
POST   /api/admin/community/direct-ads/{adId}/review       {action: APPROVE|REJECT, reason}
DELETE /api/admin/community/direct-ads/{adId}
GET    /api/admin/community/direct-ads/{adId}/stats?bounceThresholdSeconds=&startAt=&endAt=

GET/POST/DELETE /api/admin/community/advertisers[/{advertiserId}][/status]
GET    /api/app/community/slot-ads?slot=BANNER|SERVICE_HALL|SPLASH   （需登录，最多 3 条）
GET    /api/app/community/feed                                        （FEED 广告仍在混合流）
GET    /api/common/features                                           （公开，带 Token 时按校区）
```

实际事件接口沿用 `/api/app/community/direct-ads/{adId}/impression|click|landing|exit`（含 `clickId`、`dwellMs`、`landingType`），不是 §9.5 的 `/landing/start|loaded|exit` 路径。

### 10.3 广告主

- 新增 `community_advertiser` 表，字段：`advertiserId/campusId/name/contactName/contactPhone/status/remark/createdAt/updatedAt`。
- 广告通过 `advertiserId` 关联广告主；广告主停用只禁止新建关联，不追溯下线历史广告；删除为逻辑删除。
- 权限：`community:advertiser:manage`；广告审核：`community:ad:review`；广告投放管理：`community:ad:manage`。

### 10.4 与早期规划的差异

| 早期规划 | 实际实现 |
|---|---|
| `PENDING_REVIEW/ACTIVE/PAUSED/ENDED` | `DRAFT/PENDING/APPROVED/REJECTED` + `DRAFT/ENABLED/DISABLED` + `effectiveStatus` |
| `PUT` 更新 | 统一 `POST /{id}`（项目约定只用 GET/POST/DELETE） |
| `publish/pause/end` | `status` 接口 + 时间窗自动过期 |
| `GET /api/app/community/direct-ads?placement=` | `GET /api/app/community/slot-ads?slot=`；FEED 仍走 `/feed` |
| `GET /api/admin/.../stats` 无 adId | `GET /{adId}/stats` |
| 审核人展示 | 响应有 `reviewedAt`，暂未暴露 `reviewedBy/reviewerName` |
| `click_id` 由 click 接口生成 | 广告响应直接返回 `clickId`，slot-ads 每次请求生成新 `clickId` |
