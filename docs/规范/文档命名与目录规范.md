# 文档命名与目录规范

> 状态：现行 ｜ 制定：2026-10-19 ｜ 适用范围：`docs/`
> 目的：文档按类型分层、命名可预测，避免同一类文档出现多种命名格式。

## 一、目录分层

`docs/` 根目录只允许放置索引 `README.md`，其余文档按类型进入固定一级目录，不得平铺：

| 目录 | 收录内容 | 生命周期 |
|---|---|---|
| `规范/` | 长期有效的契约与规则：认证权限、工单状态机、接口参考、接口需求、文档规范 | 随功能迭代更新 |
| `设计/` | 产品、UI/UX 设计文档、设计规范、素材清单、竞品分析 | 随设计迭代更新 |
| `方案/` | 技术方案、改造方案、安装方案、可行性分析 | 立项/实施期间维护 |
| `计划/` | 有明确时间点的执行计划与批次清单 | 执行期间维护，完成后归档 |
| `报告/` | 评审、审计、交付、验收类一次性报告 | 一次性快照，按日期命名 |
| `归档/` | 已完成、被取代、不再维护的文档 | 只读，不再更新 |
| `素材/` | 图片等非文档资产，按对象建子目录 | 随素材更新 |
| `评测/RAG/` | RAG 检索评测集、评测说明与运行器 | 评测方法变化时更新 |

规则：

- 新增文档必须进入对应分类，不允许在 `docs/` 根目录新建 `.md`（`README.md` 除外）。
- 文档完成后如果不再维护，移入 `归档/`，不要留在原分类。
- 图片放 `素材/<对象>/`；脚本、配置、语料数据不放进 `docs/`（评测语料随评测目录管理）。
- 目录名用中文；已约定为技术名的目录（如 `RAG`）保留原文。

## 二、文件名格式

```text
[YYYY-MM-DD-]{主题}{类型}.md
```

### 日期

- `报告/`、`计划/`、`归档/` 中的文档必须带日期前缀，格式固定为 `YYYY-MM-DD-`，用半角连字符连接。
- `规范/`、`设计/`、`方案/` 中的文档默认不带日期；确需按版本留档时，旧版本移入 `归档/` 并补日期，而不是在文件名加版本号。
- 日期使用文档的制定日期（报告用评审日期），不随修改日期变化。

### 主题

- 主题使用中文；专有名词、缩写、产品名保留原文。
- 保留原文的常见专有名词：`API`、`AI`、`RAG`、`LLM`、`UI`、`App`、`Flutter`、`QQ`、`pgvector`、`Ardot`、`MyCC`、`ER`、`HTTP`、`JSON`、`OpenAPI`、`SQL`。
- 中英文相邻时直接拼接，不加空格、下划线、点或括号：`API需求清单`、`AI上下文与知识库接入方案`。
- 主题应能独立表达文档内容，禁止 `新建文档`、`未命名`、`test` 等占位名。

### 类型

类型必须使用下列固定词表，同一目录同类文档只允许一种写法；禁止 `design`、`spec`、`plan`、`review`、`audit`、`manifest` 等英文类型词：

| 类型 | 用途 | 示例 |
|---|---|---|
| `规范` | 长期有效的规则、契约、设计系统 | `认证与权限规范.md`、`移动端设计规范.md` |
| `说明` | 对某对象/流程的解释性文档 | `移动端页面与功能说明.md`、`评测说明.md` |
| `参考` | 供查询的接口/数据参考 | `API接口参考.md` |
| `清单` | 可逐项核对的素材/需求清单 | `勋章素材清单.md`、`API需求清单.md` |
| `方案` | 技术方案、改造/安装方案 | `pgvector安装方案.md` |
| `分析` | 可行性、竞品、评估类分析 | `LLM百科可行性分析.md` |
| `计划` | 排期、批次、执行清单 | `2026-10-17-开发计划.md` |
| `报告` | 评审、审计、交付、验收报告 | `2026-10-19-商业化审视报告.md` |

### 禁止项

- 空格、下划线、括号、版本号（`v2`、`v2.2`）、`final`/`new`/`old`/`copy` 后缀。
- 同一份文档同时出现日期后缀与日期前缀两种写法。
- 中文与英文类型词混用（如 `设计规范` 与 `design-spec` 并存）。
- 扩展名大写（统一 `.md`，图片按格式小写）。

### 例外

- 索引文件固定为 `README.md`（标准名，不翻译）。
- 代码、脚本、配置、评测语料、图片素材保留技术命名，不强制中文，例如 `run_eval.py`、`corpus/*.md`、`icon-xxhdpi.png`。

## 三、命名示例

```text
✅ 2026-10-19-商业化审视报告.md
✅ 2026-10-17-开发计划.md
✅ API需求清单.md
✅ pgvector安装方案.md
✅ AI上下文与知识库接入方案.md

❌ commercialization-review-2026-10-19.md   # 英文类型词 + 日期位置错误
❌ dev-plan-2026-10-17.md                   # 英文主题/类型
❌ mobile-design-specifications.md          # 英文类型词，主题不达意
❌ API_需求清单.md / API 需求清单.md         # 下划线/空格分隔
❌ API需求清单v2.md                          # 文件名带版本号
```

## 四、文档状态

- 文档状态统一登记在 [`docs/README.md`](../README.md) 的“文档状态”表，不在每篇文档重复维护，避免状态漂移。
- 状态取值固定为：`现行`、`待更新`、`参考`、`已归档`。
- 文档内容或元数据落后于代码时标 `待更新`，并在索引“说明”列写清差距；修复后再改回 `现行`。

## 五、引用与链接

- 文档之间优先使用相对路径 Markdown 链接，例如 `[API接口参考](../规范/API接口参考.md)`。
- 正文提及路径时可写仓库根路径（`docs/规范/API接口参考.md`），但不得只写裸文件名。
- 移动、重命名文档时必须同步更新：引用该文档的其他文档、`docs/README.md` 索引与旧名对照表。
- 历史材料（`outputs/`、`artifacts/`、`.workbuddy/`、SQL 迁移注释）中的旧路径不追改，按索引中的“旧文件名对照”换算。

## 六、新增文档检查清单

- [ ] 放入了正确的分类目录，没有留在 `docs/` 根目录。
- [ ] 文件名符合 `[日期-]主题类型.md`，类型词来自固定词表。
- [ ] 日期前缀仅用于报告/计划/归档，且为制定日期。
- [ ] 已在 `docs/README.md` 索引中登记状态、日期和说明。
- [ ] 文档内引用使用相对链接，移动时已同步更新。
- [ ] 过时文档已移入 `归档/`，索引状态改为 `已归档`。
