# 二、全生命周期交互状态清单 (Lifecycle State Checklist)

前端在还原画布时，按页面类型选择适用状态，不要求每个页面机械覆盖全部 8 态。涉及网络请求或交互动效的模块，至少覆盖：正常、加载、空、失败重试、提交中；涉及上传的再补上传失败；涉及发布/评论的再补审核态。


### 1. 正常态 (Normal State)
- 数据完整渲染，图文排版严格对齐字号梯度与行高，主副操作层级鲜明。
- 保证无任何硬编码溢出或文字折行异常。

### 2. 骨架与加载态 (Loading / Skeleton State)
- 首屏与分页拉取时展示与真实卡片高度 1:1 的浅灰骨架屏（`#F1F5F9` 微光扫光动效），禁止使用遮挡全屏的 Loading Spinner。
- 课表周视图展示 5 工作日浅灰虚线网格骨架；成绩查询展示 GPA 卡片与 3 行课程骨架。
- 列表页需同时定义：下拉刷新、加载更多、没有更多、分页到底；每页骨架结构待补规格。
- 骨架屏的具体行高、圆角、动效时长需在开发前补齐，不能只写“1:1 高度”。

### 3. 空数据态 (Empty State)
- 遵循 PRD 约束，严格使用校园官方无 Emoji 插画风格；插画素材路径待补。
  - 申请记录为空：“暂无进行中的服务与工单”，附“去服务大厅看看”。
  - 消息收件箱为空：“暂无未读消息”。
  - 搜索结果为空：“未找到相关服务或帖子”，提供热门搜索建议词。
  - 他人主页无动态：“这位同学还没有发布任何内容”。
  - 社区分区为空：“这个分区还没有内容，去发第一条”。

### 4. 加载失败与重试态 (Error / Retry State)
- 接口网络中断或 HTTP 500 时，卡片居中展示“网络连接异常，点击重新加载”与重试按钮。
- 本地有缓存数据时（如离线课表），优先展示带时间戳的缓存并提示“已加载离线内容”。
- 必须区分：
  - `401`：清除 token，跳转登录页；
  - `403`：无权限，展示可联系管理员/切换身份的说明；
  - `404`：内容已删除/不存在，展示占位；
  - `409`：重复提交或状态冲突，保留用户输入并提示具体原因；
  - `429`：限流，展示冷却时间；
  - 业务错误码（如 `REQUEST_DUPLICATE`、`EVALUATION_DUPLICATE`）按错误码表映射文案。

### 5. 表单提交中与禁用态 (Submitting / Disabled State)
- 必填项未通过前端校验时，主提交按钮置灰（`opacity: 0.5`，禁点击）。
- 点击提交后，按钮转为加载中（内嵌旋转菊花），并在收到响应前拦截重复点击。
- 提交类接口应携带 `Idempotency-Key`（`POST /api/app/service-requests` 已支持），服务端做幂等兜底。

### 6. 图片上传中与失败重试态 (Uploading & Failed State)
- 图片上传时，缩略图叠加半透明进度层（0% ~ 100%）。
- 上传失败时，卡片展示红色警示边框与纯文字提示 **“上传失败，点击重试”**（画布节点 `7:260`），点击触发单图重新上传。
- 当前 `/api/app/files` 是普通 multipart 上传，不支持断点续传；如需断点续传，需后端先支持分片上传，不能只在文档里承诺。

### 7. 弱网与离线状态 (Offline State)
- 无网络时，顶部吸顶弹出轻量黄色横幅：“当前网络不可用，部分服务可能受限”。
- 缓存范围需明确：课表、成绩快照可离线；缓存过期时间、清理策略、敏感数据保护需在开发前定义。
- “学生电子凭证”不在当前产品/接口范围内，暂不纳入离线清单。

### 8. 社区合规与审核拦截态 (Moderation State)
- 动态发布后若命中敏感词走异步机审，作者端展示 **“内容审核中，仅自己可见”** 标签。
- 违规被拦截帖子展示下架占位条，并附带 **“申请复核”** 申诉通道（建议 `POST /api/app/community/posts/{postId}/appeal`，待后端实现）。
- 当前 `docs/规范/API接口参考.md` 尚未定义 `moderationStatus` / `visibleScope` / 申诉接口，落地前需先补契约。

# 五、开发与验收注意事项 (Developer & QA Notes)

1. **零 Emoji 原则验收**：
   - QA 测试用例严禁在界面任何位置通过 Emoji 占位或文案表达情绪（例如禁止 `🎉`、`❌`、`⚠️`、`😭`）。所有状态提示使用矢量图标或高辨识度文字（如“发送失败，点击重试”、“认证成功”）。
2. **整屏周网格与周末切换**：
   - 手机默认显示周一至周五和时间列，11 节在同一屏内纵向展开；课程名按列宽缩排，重叠课程分栏，完整信息在详情弹层查看。周末课程通过「周末」按钮进入时间轴，点击日期进入对应日时间轴。大字号（>1.2 倍）默认使用列表，避免强行压缩网格文字。
   - 周次选择统一走 `19:1` 弹层（1-20 周、当前周/调课假期标记、回到本周/查看第 X 周），不在周视图内展开。
3. **工单验收与评价解耦验证**：
   - 点击“仅确认完工”可直接将工单推进至办结；点击“未修好，退回”则回退至上门处理态并触发师傅重访；评价打星不强制锁死确认流。
   - 后端无 `PENDING_CONFIRMATION` 枚举，待验收状态由 `completionSubmittedAt` / `confirmedAt` 派生；若后端新增状态，需同步更新本节与 API 文档。
4. **设备下线安全阻断**：
   - 点击“下线所有其他设备”必须强校验二次确认弹窗，下线请求成功后仅清除远端会话缓存，严禁误伤本机当前 Token。
5. **400 校验字段标红联动**：
   - 报修、申诉等动态表单收到 400 响应时，客户端根据返回的 `errors` 结构精准高亮标红对应字段，禁止使用覆盖屏幕的通用弹窗截断用户输入。
   - 当前 `Result` 只有 `message`，`errors` 结构需后端补充。
6. **提交幂等**：
   - 服务申请等 POST 接口携带 `Idempotency-Key`；前端拦截重复点击，服务端做幂等兜底。
7. **状态覆盖按页取舍**：
   - 每个页面在开发前标注适用状态（正常/加载/空/失败/提交/上传/离线/审核），不要机械覆盖全部 8 态；状态帧缺失的页面先补画布再开发。
