# 管理端视觉设计规范

> 状态：现行 ｜ 修订：2026-10-20（第三版 + UI 规范收口）｜ 范围：`/admin` 桌面管理端
> 方向：**Campus OS / 校园控制面** —— 面向多校区、多角色校园 SaaS 的运营控制台
> 关联计划：[2026-10-19-管理端开发计划](../计划/2026-10-19-管理端开发计划.md)
> 说明：第一版「墨卷」偏校刊/档案气质，不适合多租户 SaaS，已废弃，样张归档到 `artifacts/archive/admin-mojuan-preview/`。

---

## 一、为什么放弃「墨卷」

「墨卷」的问题是产品定位错位：

- 它像校刊、档案馆，适合单校区内容展示，不适合多租户、多角色、长期高频操作的 SaaS；
- 宋体大标题、纸纹、印章会降低数据密度和操作效率；
- 每个学校都希望管理台像“自己的系统”，而不是“我们的编辑风格”；
- 商业化后要做多校区、权限、配置、计费、审计，需要的是**控制面**，不是出版物。

新的方向：**Campus OS / 校园控制面**。不是再换一套皮肤，而是把管理端当“校园操作系统的控制面”来做。

## 二、设计命题

### 2.1 用户与场景

| 角色 | 高频任务 | 需要 |
|---|---|---|
| 平台运营 | 多校区切换、配置、权限、审计 | 全局上下文、稳定、可追溯 |
| 学校管理员 | 公告、社区、用户、工单、报表 | 清晰、快速、可批量 |
| 后勤/调度 | 派单、处理、SLA | 队列、状态、快捷操作 |
| 教师/辅导员 | 作业、审批、学生事务 | 任务导向、低学习成本 |

### 2.2 设计原则

1. **Context first**：当前校区/租户/身份永远可见，切换不迷路。
2. **Data plane, not cards**：数据用平面、表格、分栏承载，不用卡片墙。
3. **One accent, clear semantics**：一个品牌强调色，状态只用语义色。
4. **Density with air**：高密度表格 + 充足留白，不靠缩小字号塞内容。
5. **Keyboard & bulk**：运营是重复劳动，支持快捷键、批量、保存视图。
6. **Trust by detail**：权限、审计、危险操作确认、变更记录必须显性。
7. **Brandable, not themed**：学校可换 Logo/主色，但结构稳定。

## 三、视觉语言

### 3.1 关键词

**Tech Blue · Navy · Data Plane**  
深海军蓝控制栏，冷白工作区，科技蓝只做单一强调色；状态用语义色，数据用平面和表格承载。冷静、精确、可长期看。

> 第三版（2026-10-20）根据验收反馈调整：去掉全部渐变与装饰高光，品牌色由青绿改为科技蓝 `#2563EB`，壳层进一步压缩，数据区满宽、6 列 KPI、紧凑表格和 8–12px 区块间距，以信息密度为主要目标。

### 3.3 字体

| 角色 | 字体栈 | 用法 |
|---|---|---|
| 界面/标题 | `"Avenir Next", "Segoe UI Variable", "PingFang SC", "Noto Sans SC", sans-serif` | 标题、正文、按钮 |
| 数字/编号 | `"IBM Plex Mono", "SFMono-Regular", "Cascadia Mono", Consolas, monospace` | 指标、编号、时间、权限码 |
| 字体权重 | 400/500/600/700 | 不用 300 细字 |

**统一字号阶梯（`design-system.css` 的 `--fs-*`）**

| Token | 值 | 用途 |
|---|---|---|
| `--fs-10` | 10px | 表头、编号、元信息、KPI 脚注 |
| `--fs-11` | 11px | 辅助说明、标签、页头上下文 |
| `--fs-12` | 12px | 表格正文、表单、按钮、页签 |
| `--fs-13` | 13px | 面板标题、重点正文 |
| `--fs-14` | 14px | 页面内标题、卡片主数值 |
| `--fs-16` | 16px | 顶栏页面标题（唯一） |
| `--fs-20` | 20px | 大号数字（少量） |
| `--fs-24` | 24px | KPI 主数字 |

- 页面顶栏标题固定 16px/700；页面内的自有标题不得再出现 24–32px 展示字；
- 表格正文 12px，表头 10px/600；标签 10px；按钮和输入 12px；
- 面板标题 13px/600；KPI 主数字 24px/600，tabular-nums；
- 正文行高 1.55–1.65；不出现 10px 以下文字。

### 3.4 空间与尺寸

- 4pt 基础、2pt 修正栅格；统一 spacing token：`4 / 6 / 8 / 10 / 12 / 16 / 20 / 24`；
- 侧栏 212（1280 以下保持完整文字菜单；1024 以下抽屉）；顶栏 56；内容内边距桌面 `16px 20px 20px`，≤1024 为 12px；
- 页面区块间距 12px（总览 10px，用于放入全部运行状态）；≤840px 短屏总览自然纵向滚动；面板内边距 12–16px；面板头 34–38px；
- 控件（按钮/输入/页签）统一 30px；表格行高 38px 起，内容多的行按内容增长；导航项 30px；
- 圆角：`3px` 标签 / `4px` 按钮、输入、页签 / `6px` 面板 / `8px` 弹层；不使用 12–24 大圆角；
- 阴影：仅弹层/浮层使用 `0 12px 32px rgba(17,24,39,.12)`；页面元素只用 1px 边框。

### 3.5 设计系统落地

统一规范由 `src/main/resources/static/admin/css/design-system.css` 承载，**必须在 `campus-os.css` 之后加载**；index.html 资源版本号 `?v=techblue8`。

- 根 token：`--fs-*` 字号、`--sp-*` 间距、`--r-*` 圆角、`--h-control-sm / --h-control / --h-row / --h-topbar` 控件/行/顶栏高度、`--tk-font` / `--tk-mono` 字体栈；
- 统一覆盖：壳层、`.content` 内边距、页头、页签、按钮、输入、面板、表格、标签、KPI、弹层、登录页和响应式断点；
- 允许页面保留业务布局差异（总览/社区概览/配置中心），但字号、间距、控件高度、圆角、表格密度必须回到 token；
- 新增页面禁止直接写内联 `font-size` / `height` / `border-radius` 覆盖上述组件；需要新增 variant 时先扩展 design-system，再在页面引用。

### 3.6 背景与细节

- 工作区：冷白 `#F2F5FA`，无渐变、无装饰高光；
- 控制栏：海军蓝 `#070D1A`，细边框；
- 数据区：整幅平面、细横线、无卡片边框；
- 选中态：左侧 2px 品牌线 + 浅底；
- 图表：细线、低饱和网格、单强调色；不用 3D/渐变填充。

### 3.7 动效

- 页面切换 180ms fade/translate 4px；
- 侧栏/抽屉 220ms cubic-bezier(.2,.8,.2,1)；
- 数据刷新：数字滚动 300ms，仅一次；
- 不弹跳、不缩放、不炫光；`prefers-reduced-motion` 关闭。

## 四、布局：Rail + Command + Plane + Inspector

```text
┌────────┬──────────────────────────────────────────────┐
│ 212    │ 顶栏 56：租户/校区切换 · 搜索/命令 · 状态 · 用户│
│ 海军蓝 ├──────────────────────────────────────────────┤
│ 控制栏 │ 工作区 16/20                                   │
│        │  ┌────────────────────────────────────────┐  │
│        │  │ 页头：标题 + 上下文 + 操作             │  │
│        │  ├──────────────────────────────┬─────────┤  │
│        │  │ 主平面（表格/图表/队列）      │ Inspector│  │
│        │  │ 8–9 列                       │ 3–4 列  │  │
│        │  └──────────────────────────────┴─────────┘  │
└────────┴──────────────────────────────────────────────┘
```

### 4.1 控制栏（Rail）

- 海军蓝底；品牌 logo 30px 方形（7px 圆角），保留学校可替换；
- 顶部：产品名 + 环境徽标 `LOCAL / PROD`；Logo 32px 方形、8px 圆角；
- 租户/校区切换放在顶栏，不放在导航底部；
- 导航无圆角药丸；分组为可点击的折叠标题（30px 高、10px 字号、条目数、展开箭头），默认全部收起；
- 点击分组展开该分类，再点收起；展开状态记忆在 `localStorage`；
- 当前路由所在分组在收起时保持浅蓝底提示，展开后显示当前项左侧 2px 品牌线；
- 1280 以下保留完整文字菜单，不切换为图标栏；1024 以下使用抽屉；
- 底部：帮助、版本、用户。

### 4.2 顶栏（Command）

- 左：面包屑 + 租户/校区切换；
- 中：全局搜索/命令面板（⌘K）；搜索输入 30px 高；
- 右：任务中心、通知、帮助、环境状态、用户；
- 56px 高，固定；不使用大搜索胶囊，用平面输入。

### 4.3 页头

- 页面标题 16px/700；概览页隐藏独立页头，标题只保留在顶栏；
- 下方一行上下文（校区/筛选/统计）11px，统一来自路由 subtitle；
- 操作最多 2 个主按钮 + 更多，按钮统一 30px；
- 不使用 oversized editorial 标题。

### 4.4 平面（Plane）

- **表格**：全宽、sticky 表头、首列固定、无外框、行 hover；表头 10px，正文 12px；
- **队列**：左侧列表 + 右侧详情（分栏），不弹窗；
- **看板**：列 + 卡片仅用于拖拽任务，不做仪表盘卡片墙；
- **图表**：整幅平面，标题/图例轻量；
- **配置**：左索引 + 右表单（master-detail），非卡片。

### 4.5 Inspector（右侧检查器）

用于详情、配置、审计 diff：

- 宽 320–400；可折叠；
- 分区标题 11px 等宽；
- 键值行 13px，label 左、value 右；
- 底部固定主操作；
- 危险操作区用 danger 线 + 二次确认。

## 五、组件

### 5.1 按钮

- 主：品牌科技蓝实底、白字、4px 圆角、30px 高；
- 次：白底、1px line、ink；
- 危险：danger 描边/实底；
- 文本：仅链接场景；
- 禁用：40% 透明 + not-allowed。

### 5.2 状态

- 用 **dot + 文案** 或 **小方块 + 文案**，不用胶囊；
- 颜色：success/warning/danger/info/neutral；
- 状态必须带文字，不只靠颜色；
- 状态变更记录在审计。

### 5.3 表格

- 表头 10px/600，正文 12px；行高 38px 起；
- 数字右对齐 tabular-nums；
- 长文本 2 行截断；
- 批量选择 hover 出现；选中行左侧品牌线；
- 空态：一句解释 + 主操作，不用插画。

### 5.4 表单

- Label 上、11–12px；必填 danger `*`；
- 输入框/选择器 30px 高、1px line、4px 圆角；
- focus：品牌线 + 2px 外发光（仅 2px，不炫光）；
- 错误：danger 线 + 11px 文案；
- 保存条 sticky，显示最后保存/变更数。

### 5.5 数据展示

- 指标带：4–6 列、细竖线、24px 数字；KPI 卡固定 87px 高；社区概览固定 6 列；
- 趋势图：1.5px 线、3 条横网格；总览趋势在 1440/1904 完整露出运行状态；
- 分布：条形/环形，但只在确有比例时；
- 不要装饰性 sparkline 泛滥。

### 5.6 空/错/加载

- 空：标题 + 说明 + 主操作；
- 错：错误码 + 重试 + 联系支持；
- 加载：骨架线/表格骨架，不用居中大 spinner；
- 无权限：解释 + 申请权限。

## 六、配置中心与 SaaS 化

### 6.1 多租户上下文

- 顶栏固定展示 `租户 / 校区 / 角色`；
- 切换后所有页面数据刷新，URL 带 `tenant`/`campus`（或 session 上下文）；
- 配置项显示作用域：平台 / 租户 / 校区 / 组织；
- 只读/可编辑由角色权限决定。

### 6.2 配置中心布局

```text
左侧索引（14 域）       右侧配置面板
────────────────────────────────────────
平台信息                01 学校与品牌
功能开关                02 对外信息
登录与安全              03 运行开关
身份与组织              04 只读环境配置
服务与工单              ...
```

- 每项显示：来源标签（RUNTIME/SECRET/ENV/ENTITY）、当前状态、帮助、最后修改；
- 密钥只显示“已配置/末四位”、测试按钮；
- 保存条显示变更数、最后保存人；
- 变更记录在右侧 Drawer，不跳页。

### 6.3 管理台壳层

- 登录页：左品牌/右登录表单，展示环境与 SSO；
- 租户选择：首登或多租户用户进入选择页；
- 权限不足：保留导航，页面内 403 说明；
- 环境标识：LOCAL/DEV/PROD 徽标常驻，防误操作。

## 七、页面模板

### 7.1 工作台（Operations Overview）

- 顶部：日期/值班/环境；
- 指标带：待办/今日/异常/触达；
- 主平面：趋势 + 待办表格；
- Inspector：异常队列、系统健康、值班信息；
- 不做四张独立 KPI 卡片。

### 7.2 档案列表（Data Table）

- 页头 + 筛选条（inline）+ 批量条 + 表格；
- 右侧 Inspector 打开详情，不跳页；
- 支持保存筛选、列配置、导出。

### 7.3 配置中心（Master-Detail）

- 左索引 + 右分节表单；
- 密钥/环境变量只读状态；
- sticky 保存条。

### 7.4 审批/处置（Queue + Detail）

- 左队列（可批量），右详情；
- 状态、SLA、操作在 Inspector；
- 键盘 j/k、批量 approve/reject。

### 7.5 登录

- 左：平台品牌、版本、环境、合规声明；
- 右：账号/SSO/二维码，清晰错误；
- 不做营销大图。

### 7.6 AI 基座（供应商 / 模型 / 默认 / 测试）

AI 基座是配置面，不是运营大屏，仍遵守数据面规则：**一个页签一个主平面，不堆卡片墙**。

**页签结构**

- 模型配置：左供应商索引（262px，列表项 48px，名称/编码/模型数/启停点）＋右主平面；主平面 = 供应商 Hero + 模型表 + 接入概览；
- 模型列表：跨供应商汇总条 + inline 筛选 + 密集表格 + 编辑弹层；底部三块「类型分布 / 供应商分布 / 操作提示」，分布条用 5px 实心品牌条，≤1280 收起；
- 默认模型：两栏（左 6 类默认模型列表，右全局设置与上下文预算），保存条在栏底；
- 测试：左 SSE 对话面（1fr）＋右 320px 检查器（测试目标 / 运行信息 / 快捷测试）。

**密度与组件**

- Hero：34px 头像、13.5px 供应商名、5 列 meta（Base URL / 凭据 / 模型 / 上次检查 / 检查结果），底部启停行；
- 页签统一 30px 高、4px 圆角、12px 字号；模型表表头 29px、行 38px、固定列宽；类型用 3px 小标签，启用用 32×18 switch，操作只用文本链接；
- 默认模型行：首字色块 + 类型名 + 模型名 + 原生 select + 清除链接，行高 44–48；全局设置 3 列表单，分组标题 10px；
- 测试气泡：用户气泡品牌蓝、AI 气泡面板底；元信息 9px 等宽；错误用 danger 条，不覆盖历史回答；
- 接入概览：能力覆盖（6 类真实模型计数 + 4px 实心条）／接入检查（协议、凭证、上次检查、结果）／路由规则三块；条只用品牌实色，**仍零渐变**；
- 所有空态显示 0 或「尚未检查/未配置」，不编造模型、连接结果或 token 用量。

**状态与响应式**

- 供应商/模型启停即时 toast；连通检查显示检查中，成功/失败均有结果文案；弹层统一 8px 圆角、20px 内边距；
- 默认模型下拉只列出「已启用供应商 + 已启用模型」，无可用模型时保留「选择模型」占位；
- ≤1280 收起接入概览（保证首屏不裁切）；≤1024 供应商列表与主平面上下排列，页面自然滚动；
- Dark 下表格头、气泡、输入区、概览卡必须换为 Dark token，不允许白底白字；
- SSE 的 `done` 为正常结束，不得把关闭 chunked 的网络噪声显示为业务错误；失败必须显示错误态。

## 十一、数据可视化规范（管理端重点）

> 用户明确要求“多数可视化统计信息”，因此数据可视化不是工作台的装饰，而是管理端的核心信息层。

### 11.1 图表色彩（与品牌色分离）

品牌色只用于主操作与当前项；图表使用一组低饱和、可区分的分析色：

| Token | 色值 | 用途 |
|---|---|---|
| `--chart-1` | `#2563EB` | 主趋势 / 当前周期 |
| `--chart-2` | `#60A5FA` | 对比周期 / 次级趋势 |
| `--chart-3` | `#B45309` | 警告 / 待处理 |
| `--chart-4` | `#9A3412` | 超时 / 负向 |
| `--chart-5` | `#4D7C0F` | 完成 / 正向 |
| `--chart-6` | `#475569` | 中性 / 其他 |
| `--chart-7` | `#0369A1` | 信息 / AI |
| `--chart-8` | `#86198F` | 社区 / 内容 |

规则：
- 不使用彩虹色、不做渐变填充；
- 同屏不超过 5 个主色；
- 颜色不足以区分时用线型/标记/标签；
- 所有图表必须有单位、时间范围、数据来源、空态。

### 11.2 图表类型选择

| 场景 | 图表 |
|---|---|
| 指标随时间变化 | 折线图（1–2 条）、面积仅作辅助 |
| 分类对比 | 横向条形图（优于柱状图，适合中文标签） |
| 流程转化 | 横向漏斗/阶段条 |
| SLA/达标率 | 子弹图或水平进度，不用仪表盘 |
| 时段分布 | 热力图（星期 × 小时） |
| 组织/校区对比 | 分组条形 + 排行榜表 |
| 用户留存 |  cohorts 矩阵 |
| 内容分布 | 矩形树图/条形，不用 3D 饼图 |
| 单一占比 | 环形图，且 ≤5 类 |

### 11.3 工作台可视化布局

```text
指标带（4–6 个）
────────────────────────────────────────────
主趋势（工单/服务申请）         SLA 达标率
────────────────────────────────────────────
漏斗：提交→受理→派单→办结→评价
────────────────────────────────────────────
热力图：工单时段分布            社区/内容趋势
────────────────────────────────────────────
异常队列 / 待办表格             系统状态
```

- 指标带：同比/环比、目标值、数据时间；
- 主趋势支持“近 7 天 / 30 天 / 本学期”切换；
- 漏斗每阶段显示数量、转化率、平均耗时；
- 热力图可点击下钻到工单列表；
- 图表统一“图 01 / 数据源 / 时间”标注。

### 11.4 数据分析页（新增）

路由：`#/analytics`，五个标签：

1. **总览**：活跃、办结、SLA、满意度、内容、AI 使用；
2. **服务**：申请量、办结率、超时率、平均时长、满意度、组织排行；
3. **社区**：发帖/评论/互动、分区分布、举报/处置、优质内容；
4. **用户**：新增、活跃、留存、身份/组织分布、登录方式；
5. **AI**：会话量、token/成本、命中知识库、失败率、满意度。

- 顶部日期/校区/组织筛选；
- 每个图表可导出 PNG/CSV；
- 所有图表有表格兜底，避免只靠颜色；
- 数据源必须来自聚合 API，不在前端拼假数据。

### 11.5 图表实现

- 统一使用 ECharts 封装 `ChartCard` / `useChart`；
- 主题从 CSS token 生成，Light/Dark 切换重绘；
- 容器支持 resize、loading、empty、error；
- 大数字用 tabular-nums，坐标轴 10–11px；
- 图表放在 6px 圆角平面面板中，标题/图例 10–11px，图例用小色块而非胶囊。

## 十二、用户管理设计（管理端）

> 用户管理是管理端最重要的“身份控制面”，从“改角色”升级为用户全生命周期管理。

### 12.1 信息架构

```text
用户与组织
├── 用户管理
│   ├── 用户列表
│   ├── 用户详情（Drawer/右侧 Inspector）
│   ├── 批量导入
│   └── 身份审核
├── 角色权限
├── 组织架构
└── 登录设备
```

### 12.2 用户列表

列：

| 列 | 内容 |
|---|---|
| 用户 | 头像/昵称/用户名/UID |
| 身份 | 学生/教师/后勤/管理员；多身份显示主身份 |
| 组织 | 学院/部门/班级 |
| 角色 | 角色标签，最多 2 个 + 更多 |
| 授权 | BASIC/PENDING/AUTHORIZED/REJECTED |
| 状态 | 启用/停用/锁定/归档 |
| 登录 | 最近登录时间/方式/IP 所属地 |
| 风险 | 异常登录/未绑定/资料缺失 |
| 操作 | 查看/授权/角色/停用/更多 |

筛选：
- 关键词、校区、身份、组织树、角色、授权状态、账号状态、登录方式、注册时间、最近活跃、是否官方号；
- 支持保存视图（如“待审核学生”“后勤未授权”“7 天未登录”）。

批量：
- 批量授权/拒绝、批量分配角色、批量停用/启用、导出；
- 所有批量操作二次确认 + 审计。

### 12.3 用户详情（右侧 Inspector）

Tabs / Sections：

1. **基本资料**：昵称、用户名、UID、手机、邮箱、身份、注册时间；
2. **组织与身份**：主组织、兼任组织、班级/专业、身份来源（自报/导入/SSO）；
3. **角色与数据范围**：角色绑定、组织、dataScope、生效时间；
4. **登录与安全**：登录方式、设备、IP、最近登录、强制下线、重置密码、MFA 状态；
5. **关联业务**：服务申请、工单、帖子、作业、评价；
6. **操作记录**：谁在何时改了什么（审计 diff）。

### 12.4 用户操作清单

| 操作 | 说明 | 权限 |
|---|---|---|
| 编辑资料 | 昵称/手机/邮箱/身份（受控） | `system:user:manage` |
| 授权审核 | 通过/拒绝 + 原因 + 通知 | `system:user:manage` |
| 分配角色 | 多角色 + 组织 + 数据范围 | `system:user:manage` |
| 设为官方 | 官方头衔 | `system:user:manage` |
| 批量导入 | 模板下载/上传/映射/预览/冲突处理/提交 | `system:user:import` |
| 重置密码 | 生成临时密码/发送短信 | `system:user:manage` |
| 强制下线 | 指定设备/全部设备 | `system:user:manage` |
| 停用/启用 | 停用立即踢出会话 | `system:user:manage` |
| 归档 | 毕业/离职，保留审计与历史 | `system:user:manage` |
| 导出 | 当前筛选结果，脱敏 | `system:user:export` |

### 12.5 导入流程

```text
下载模板 → 上传 CSV/XLSX → 字段映射 → 校验预览（新增/更新/冲突）
→ 选择策略（跳过/覆盖/合并）→ 提交异步任务 → 结果报告
```

- 支持学号/工号、姓名、身份、学院、专业、班级、手机、邮箱、角色；
- 重复学号默认更新，不重复建号；
- 错误行可下载；
- 导入任务写入审计，可回滚/撤销本批次（未产生业务数据时）。

### 12.6 身份模型调整

当前 `sys_user.identity_type` 是单值，但真实校园存在多身份：

- 学生 + 助教、教师 + 管理员、后勤 + 调度；
- 建议保留 `identity_type` 作为主身份（展示/默认视图），新增 `sys_user_identity` 表支持多身份；
- 角色仍通过 `sys_user_role` 控制权限；
- 组织关系通过 `sys_user_organization` 支持多组织；
- 授权状态按身份/组织维度审核，避免“一次授权全平台”。

### 12.7 用户相关 API

```text
GET  /api/admin/users                       列表/筛选/排序
GET  /api/admin/users/{id}                  用户详情聚合
PUT  /api/admin/users/{id}/profile          资料/身份（受控）
PUT  /api/admin/users/{id}/role-bindings    角色+组织+数据范围
POST /api/admin/users/{id}/authorization    授权审核
POST /api/admin/users/import/preview        导入预览/校验
POST /api/admin/users/import                提交导入任务
GET  /api/admin/users/import/{jobId}        导入结果
POST /api/admin/users/{id}/reset-password   重置密码
GET  /api/admin/users/{id}/sessions         登录设备
DELETE /api/admin/users/{id}/sessions/{sid} 强制下线
GET  /api/admin/users/{id}/audit            操作记录
```

### 12.8 用户页 UI 要点

- 列表和 Inspector 同屏，不跳页；`j/k` 切换用户；
- 用户头像使用姓氏首字 + 身份色，不做花哨渐变；
- 授权状态、账号状态、风险提示用 dot + 文案，不用彩色胶囊墙；
- 批量条只在选中时出现；
- 导入使用独立向导页/抽屉，预览表与错误行清晰；
- 所有写操作写审计，并在详情“操作记录”可见；
- 页面顶部显示当前租户/校区，避免跨校区误操作。
