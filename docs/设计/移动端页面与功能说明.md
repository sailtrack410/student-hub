# 移动端（学生端）页面与功能说明

> 用途：本文档写给**前端设计师**，作为移动端画布的设计输入。逐页说明"这个页面为什么存在、给谁用、包含哪些区块、有哪些状态"，设计师据此逐屏出画布。
> 事实基准：微信小程序 `student-hub-weapp`（已实现全部 22 页，2026-10-15 核对）；App（Flutter，`SmartCampus/app`）目前只有登录/首页/服务大厅/邮箱绑定 4 页，**其待设计清单即本文档的页面清单**。

### 1.2 五条硬约束

1. **全站不使用 emoji**：所有图标用生成图标/矢量图标或吉祥物，画布上不要出现 emoji 占位。
2. **优先使用平台原生组件**（小程序原生组件 / Flutter 原生控件），不引入重型 UI 库。
3. **服务入口是动态下发的，数量可变**：首页宫格与大厅分组都由服务目录接口驱动（`utils/directory.js` 是唯一数据源），支持后台增删。**画布必须考虑 4/5/6/8 个入口的自适应排布**，不能按固定数量出图。
4. **按钮文字必须 flex 垂直水平居中**：微信 `button` 默认宽度与行高来自属性选择器，不 flex 会上下不居中——画布上按钮请标注"文字居中"。
5. **已有 4 张空态/错误插画**（`student-hub-weapp/assets/empty/`）：申请为空、通知为空、搜索为空、网络错误。**请沿用同一插画风格**，不要另起一套视觉；如需新增空态（如社区为空、工单为空）请补同风格插画。

### 1.3 两端差异与现状

| | 微信小程序（已实现） | App（Flutter，待设计） |

| 登录 | `wx.login` 静默登录（无登录页交互） | 学号/密码登录 + 注册 + 邮箱绑定（已实现） |
| 其余页面 | 按本文档逐页实现 | **按本文档逐页设计** |

## 二、信息架构与导航关系

```
底部 tab
├─ 首页 home/index
│   ├─ 我的课表 ──────────→ 课表 schedule/index
│   ├─ 我的申请（进行中） ─→ 申请详情 request/detail
│   ├─ 常用服务宫格 ──────→ 服务详情 service/detail → 申请表单 service/apply
│   ├─ 社区入口 ─────────→ 社区 community/index
│   └─ 未完成事项引导卡 ──→ 按未完成项跳转（如未认证教务 → jw/auth）
├─ 服务（大厅） service/index
│   └─ 分组列表（动态） ──→ 服务详情 service/detail → 申请表单 service/apply
├─ AI助手 assistant/index
│   └─ 会话页（语音/图片提问，可查课表与申请进度）
├─ 社区 community/index
│   ├─ 帖子详情 community/detail（评论/点赞/置顶）
│   ├─ 发帖 community/publish
│   ├─ 作者主页 community/author
│   └─ 私信收件箱 community/inbox → 会话 message/chat
└─ 我的 profile/index
    ├─ 进行中 / 已办结 / 未读消息（统计三格）
    ├─ 我的申请 request/list → request/detail
    ├─ 我的工单 order/list → order/detail（服务人员身份可见）
    ├─ 我的消息 notification/list
    ├─ 社区 ─────────────→ community/index
    └─ 个人中心 profile/center（资料、教务绑定/解绑、手机号）

独立入口：教务认证 jw/auth（首次绑定、失效重认证）、服务评价 evaluation/index（申请办结后进入）
```

## 三、逐页说明

> 每页给出：**用途 / 进入方式 / 画布需覆盖的区块 / 主要交互 / 必须画的异常与边界态 / 数据来源**。接口名仅用于对齐数据范围，画布不必体现。

### 3.1 首页 `pages/home/index`

- **用途**：一屏回答学生三个问题——"我接下来要上什么课""我的事办到哪了""我要办事去哪"。
- **进入**：启动默认页，tab 第 1 项。
- **区块**（自上而下）：
  1. **问候头 hero**：时间问候语 + 用户昵称（正课时间可提示"第几节有课"）+ 横幅图/渐变卡。
  2. **快捷入口**（每行 4 格）：**课表 + 6 个服务 + 更多**，固定 8 格布局；6 个服务当前为宿舍报修、请假申请、在读证明申请、活动场地申请、校园事务咨询、教室与公共区域报修（名称与图标由目录下发）。
  3. **我的课表卡**：今日/下一节课摘要（课程名、时间、地点），点击进课表页；未绑定教务时显示"去认证"。
  4. **我的申请卡**：进行中申请 1-2 条（标题 + 状态徽标 + 时间），右侧"全部 ›"；**无申请时替换为空态插画**（现成插画见 1.2 第 5 条）。
  5. **常用服务**：4 个服务卡（名称 + 说明 + 箭头），由目录下发。
  6. **社区入口条**：社区 logo + 标题 + 副标题 + 箭头。
  7. **引导卡（吉祥物）**：吉祥物 + 引导文案 + 按钮（用于引导完成未完成事项）。
- **交互**：下拉刷新；各卡点击跳转；未读消息红点。
- **必须画的态**：目录加载失败（不打断首页，宫格降级）、课表未绑定、申请为空、加载骨架。
- **数据**：目录、课表视图、我的申请分页、未读计数。

### 3.2 服务大厅 `pages/service/index`

- **用途**：全部可办事项的分类总入口（二级：分类 → 事项 → 表单）。
- **区块**：**分组列表**（分组名 + 事项卡列表：图标、名称、一句话说明、右侧箭头）。分组与顺序由目录下发，**当前真实数据为 5 个分组、7 个事项**：

| 分组 | 事项 |
|---|---|
| 报修服务 | 宿舍报修、教室与公共区域报修 |
| 事务办理 | 请假申请、活动场地申请 |
| 证明开具 | 在读证明申请 |
| 咨询与指引 | 校园事务咨询 |
| 校园应用 | 我的课表 |

- **交互**：下拉刷新、分组内点击进详情；后勤身份会自动隐藏部分事项（请假/场地/在读证明/课表）。
- **必须画的态**：空分组、目录加载失败可重试、**事项数量不定时的列表延展**（画布请按"每分组 1-3 项"与"某分组只有 1 项"两种情况出图）。
- **数据**：服务目录。

### 3.3 服务详情 `pages/service/detail`

- **用途**：让用户在申请前搞清楚"能不能办、要多久、要交什么"。
- **区块**：事项图标与名称、摘要、办理说明（富文本/换行文本）、**办理时限（SLA 小时）**、需要提交的材料提示、底部主按钮"立即申请"。
- **必须画的态**：事项停用/下架、说明为空、长文本折行。

### 3.4 申请表单 `pages/service/apply`

- **用途**：提交申请。
- **区块**：事项名（顶部还原上下文）、**动态表单**（字段由后端 `form_schema` 下发，共 6 种类型：`input` 单行文本 / `textarea` 多行文本 / `select` 下拉 / `date` 日期 / `number` 数字 / `image` 图片上传）、必填标记、底部"提交申请"。
- **交互**：必填项前置校验（给出友好提示而不是提交后才报错）、图片选择与压缩上传、提交中禁用按钮防重复提交。
- **必须画的态**：字段类型可多可少（**画布要覆盖 1 字段与 8+ 字段两种情况**）、上传中/上传失败、提交成功与失败、重复提交提示。

### 3.5 我的申请列表 `pages/request/list`

- **用途**：查看自己所有申请及进度。
- **区块**：状态筛选（全部/进行中/已办结——可做页签）、申请卡（标题、事项名、提交时间、状态徽标、缩略图可选）、分页。
- **必须画的态**：空列表（引导去大厅）、加载中、分页到底。

### 3.6 申请详情 `pages/request/detail`

- **用途**：进度追踪 + 关键节点确认（本系统最复杂的页面之一）。
- **区块**：状态时间轴/进度条、申请内容回显（含图片）、**工单协商区**（服务人员提出的时间/安排，学生可"确认"或"驳回"）、相关工单信息、底部操作（**撤销申请**、办结后**去评价**）。
- **必须画的态**：待处理/处理中/待确认/已完成/已撤销/已驳回（**至少 6 态**）、驳回理由展示、无工单时隐藏协商区。
- **数据**：申请详情、撤销、确认/驳回工单确认。

### 3.7 服务评价 `pages/evaluation/index`

- **用途**：办结后对服务打分与留言（也是服务质量数据来源）。
- **区块**：星级评分（1-5）、快捷评价标签、文字评价（多行，可留空？按后端要求）、提交。
- **必须画的态**：已评价过（不可重复）、评价成功回执、低分提示语。

### 3.8 通知列表 `pages/notification/list`

- **用途**：系统/工单/申请/评价/社区通知的统一收件箱。
- **区块**：通知列表（标题、摘要、时间、未读圆点、类型徽标）、"全部已读"、点击进详情或关联业务页。
- **必须画的态**：空态、全部已读后的视觉、未读计数与 tab 角标。

### 3.9 我的工单列表 `pages/order/list`（服务人员/后勤）

- **用途**：服务人员查看被指派的工单并推进。
- **区块**：工单卡（标题、申请类型、地点、时限 SLA 倒计时、状态徽标）、操作按钮（**接单/开工**、**完成**）。
- **必须画的态**：无指派、超时告警、状态不可操作时的禁用按钮。

### 3.10 工单详情 `pages/order/detail`（服务人员/后勤）

- **用途**：现场作业的记录与闭环。
- **区块**：工单信息、申请人信息与联系方式、**现场照片**（到达拍照、完工拍照）、操作区（开始处理、提交完工）。
- **必须画的态**：必拍未拍的校验、上传进度、已完成只读。

### 3.11 教务认证 `pages/jw/auth`

- **用途**：绑定学校教务账号（后续课表/成绩依赖它）。
- **区块**：说明文案（**代查授权说明：凭据加密存储、仅用于代查课表/成绩**）、学号输入、密码输入、**图形验证码**（点击刷新）、提交；已绑定态展示账号与"解除绑定"。
- **必须画的态**：未绑定 / 已认证 / **已失效需重新认证** 三态、验证码错误、账号密码错误、频繁操作限流、绑定冲突（该账号已被他人绑定）。

### 3.12 课表 `pages/schedule/index`

- **用途**：周课表（本系统使用频率最高的页面）。
- **区块**：学期切换（下拉，含"第几周"提示）、**星期 × 节次网格**（每节次对应作息时间；一节课多时段需并格）、课程块（课程名/地点/教师，**单双周与周次范围**需要视觉区分）、当天课程高亮。
- **必须画的态**：未导入/未绑定、该周无课、**单双周课与非整周课的视觉区分**、并格课程（连续节次合并）、长课程名折行。

### 3.13 个人中心 `pages/profile/index`（tab"我的"）

- **用途**：账号与业务聚合入口。
- **区块**：
  1. **头部**：头像 + 昵称 + **身份标识行**（图标 + 身份文字：学生/后勤等，由教务认证驱动）+ 未登录时"去登录"按钮。
  2. **统计三格**：进行中 / 已办结 / 未读消息（数字可点，分别进申请列表/已办结/通知）。
  3. **菜单列表**：我的工单、我的申请、我的消息、社区、个人中心、退出登录（每项含图标、文字、右侧箭头或数值）。
- **必须画的态**：未登录（头部替换为登录引导）、身份标识缺失、统计为 0。

### 3.14 个人中心-资料 `pages/profile/center`

- **用途**：改昵称/头像/手机号、查看教务绑定信息与解绑。
- **区块**：头像与昵称编辑、手机号（微信授权获取或手填）、教务信息（SSO 账号、姓名、年级、院系、专业、班级、**教务学号**、最后认证时间、会话有效期）、解绑按钮。
- **必须画的态**：手机号获取失败可手填、教务未绑定、解绑二次确认。

### 3.15 社区首页 `pages/community/index`

- **用途**：校园内容流（tab"社区"）。
- **区块**：**分区/话题横滑条**（如"普通"等，含热门话题）、**帖子流卡片**（标题、正文摘要、**图片九宫格**、话题标签、作者头像与昵称、浏览量/评论数/点赞数、置顶标识）、右下发帖按钮（FAB）、上滑加载更多。
- **交互**：点赞（可取消）、下拉刷新、点击进详情、点作者进主页。
- **必须画的态**：空分区、加载中、加载失败重试、**长文折行、多图（1/2/3/4/9 张）网格、无图纯文字帖**、点赞动画可选。
- **数据**：分区、热门话题、帖子分页、点赞。

### 3.16 帖子详情 `pages/community/detail`

- **用途**：看帖 + 评论互动。
- **区块**：帖子正文（标题/正文/图片/话题）、作者行（头像、昵称、关注入口可选）、**评论列表**（支持回复某条评论、评论点赞、作者置顶评论标记）、底部输入条（文字、图片、表情可选）。
- **必须画的态**：评论为空、评论长文、被回复的嵌套样式、**自己发的评论（带删除入口）**、加载更多评论。
- **规划新增（等后端）**：帖子/评论的**举报入口**（长按菜单或右上角"…"）、内容被治理后的状态（见 4.1）。

### 3.17 发帖 `pages/community/publish`

- **用途**：发布内容。
- **区块**：分区选择、标题（限 80 字）、正文（限 2000 字，字数计数）、**图片上传（最多 9 张）**、话题选择（可从热门话题选，也可新建）、发布按钮。
- **必须画的态**：未选分区的校验、字数超限、图片上传中/失败、发布中防重复、发布失败保留草稿（建议）。

### 3.18 作者主页 `pages/community/author`

- **用途**：了解发帖人（校园场景便于建立信任）。
- **区块**：头像与昵称、**身份信息行**（学院/专业/班级/性别，缺失时显示"未填写"）、他的帖子列表（最多 20 条）、可选的"发私信"入口。

### 3.19 私信收件箱 `pages/community/inbox`

- **用途**：私信会话列表 + 社区类通知。
- **区块**：会话列表（对方头像、昵称、最后一条消息、时间、未读红点）、社区通知区（点赞/评论/系统）。

### 3.20 私信会话 `pages/message/chat`

- **用途**：一对一聊天。
- **区块**：消息气泡（左右区分、时间分组、**图片消息**）、底部输入条（文字 + 图片）、发送中/发送失败重发。
- **必须画的态**：图片消息与文本消息混排、加载历史、对方不在线（无实时连接时降级）。

### 3.21 AI 助手 `pages/assistant/index`（tab"AI助手"）

- **用途**：自然语言问校园事务，支持语音与图片提问，可查本人课表与申请进度。
- **区块**：会话区（用户气泡、AI 气泡，**支持 Markdown 渲染**：列表/加粗/表格/代码）、**推荐问题**（首次进入）、输入区（文本 + **语音长按录制** + 图片选择）、发送中状态。
- **必须画的态**：空会话（引导 + 推荐问题）、思考中（打字机/加载）、回答失败可重试、语音录制中、图片上传中、长回答折行与代码块样式。

### 3.22 登录 `pages/login/index`

- **用途**：小程序侧为静默登录（无交互页）；**App 端为学号/密码登录 + 注册（用户名/姓名/密码）+ 邮箱绑定**。
- **必须画的态**：账号或密码错误（红色提示条，展示后端原文）、网络异常、密码规则校验（8 位以上且含字母与数字）、注册成功自动登录。

## 四、待设计的新增能力（已列入开发计划）

### 4.1 社区举报与内容状态（后端已完成，界面待设计）

- **举报入口**：帖子详情、评论（长按/更多菜单）、私信会话、作者主页各需要一处入口。
- **举报弹层**：**原因单选**（广告营销 / 辱骂攻击 / 色情低俗 / 违法违规 / 泄露隐私 / 其他）+ 补充说明（选填，500 字）+ 提交；提交成功后给"已收到，处理结果会通知你"的回执。
- **内容状态呈现**（治理后可能出现）：
  - 「仅自己可见/审核中」占位卡（内容被隐藏时，作者看到"你的内容因违规被下架"说明）；
  - 「该内容已被删除」占位（他人视角）；
  - 「作者已注销」作者信息位。
- **处罚态**：被限制发言的用户在发帖/评论入口显示提示（"你已被限制发言，暂时无法发布内容"）。

### 4.2 成绩查询（规划，需先确认教务接口）

- 学期切换 + 成绩列表（课程名/学分/绩点/分数）+ **合计区**（已修学分、已获学分、平均分、挂科数）+ 挂科高亮；**不做排名榜**。

### 4.3 校内地图（规划，成本最高，先定路线）

- 建议第一版：**自绘校园图 + 楼栋 POI 打点**（不做室内/3D、不做路径导航）；区块为楼栋列表 + 地图点选 + "我在哪/去这里"；需留后台 POI 维护入口。
