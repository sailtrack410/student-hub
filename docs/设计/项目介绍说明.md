# 绵城一码通（Student Hub）项目介绍

> 状态：现行 ｜ 用途：对外展示（社区板块重点版） ｜ 更新：2026-11-02
> 本文面向演示、汇报、参观讲解场景，按"30 秒版 → 社区核心板块 → 其他功能 → 技术 → 质量 → 状态"组织，可整段直接使用。

## 30 秒版本

绵城一码通是一套面向高校场景的一站式校园服务平台。它的核心板块是**校园社区**：四个内容分区、图文帖子与评论互动、站内私信、完整的举报申诉与内容治理、以及"广告主 → 投放 → 审核 → 数据埋点"的全链路广告体系，仅社区一个模块就有 11 个控制器、103 个接口，是全系统最重的业务板块。围绕社区，平台还提供课表查询、服务申请报修、电费查询和 AI 助手；学生在小程序/App 上使用，后勤与管理员通过 Web 管理端运营。系统配套 154 项后端测试与 93 项 App 测试，已部署生产并发布 App 1.1.6 版本。

## 项目背景

校园事务分散在多个系统里：课表在教务系统、报修靠电话和群聊、失物寻物靠朋友圈转发、二手交易靠 QQ 群刷屏。学生要在五六个入口之间来回切换，信息触达靠"碰运气"，校园里缺少一个把"人和人、人和事"真正连起来的场。

绵城一码通的答案是：**以社区为枢纽的一站式校园平台**——社区解决"人和人的连接与信息流转"，服务大厅和工单闭环解决"人和事的办理"，管理端把两边的运营与治理都管起来。

## 校园社区：平台的核心板块

社区是本系统投入最重、打磨最深的板块：11 个控制器、103 个接口，覆盖"内容生产 → 消费互动 → 私信连接 → 治理管控 → 商业变现 → 数据回流"的完整闭环。

**1. 内容与互动**
失物招领、二手交易、学习咨询、校友杂谈四个分区；图文发帖、评论、帖子/评论两级点赞、评论置顶、收藏、"不感兴趣"隐藏、删帖一应俱全；热门话题聚合（`topics/hot`）让热点自然浮出；作者主页（`authors/{id}`）沉淀个人内容资产。

**2. 站内私信（IM）**
独立的私信系统：会话列表、联系人、在线状态（presence）、未读数、消息送达回执，配合 WebSocket 实时推送，让"失物认领""交易砍价"这类沟通不出平台即可完成。

**3. 内容治理闭环**
不是"只发不管"：学生侧可发起举报与申诉；管理端提供举报处置与批量处置、申诉处理、内容隐藏/恢复、用户制裁与解除制裁、敏感词库（支持批量导入导出）、审核话术模板、分区/话题管理（排序、推荐、合并、统计）、帖子置顶与官方回复。治理链路从"发现 → 处置 → 申诉 → 解封"全部线上化。

**4. 商业化与广告体系**
全链路广告能力：广告主管理、投放计划、广告素材、直投广告四层结构；广告走"草稿 → 送审 → 过审 → 上架"审核流，仅审核通过且上架的广告可进入 Banner/服务大厅/开屏三大广告位并混排进信息流；曝光、点击、落地页打开/退出全埋点上报，效果数据可查。

**5. 官方运营与激励**
官方账号可直接发布、置顶帖子、以官方身份回复；勋章成就体系激励活跃内容生产；配合管理端的创作者运营、内容日历与数据看板（含导出），社区运营有抓手、有数据。

**6. 性能工程**
社区是性能优化样板：信息流批量组装，单屏 SQL 从 31 条收敛到 4 条，消灭 N+1；收藏状态批量回显零额外查询；"不感兴趣"由服务端权威过滤（V99 行为表 + 唯一键防重），登录换设备体验一致。

## 其他核心功能

**服务大厅与工单闭环**：服务目录后台动态下发、schema 驱动动态表单；申请 → 派单 → 办结 → 评价全链路；报修类工单"现场拍照 → 完工拍照 → 报修人确认/退回"照片闭环，内置 12 类报修类型与 21 栋宿舍楼字典。

**课表与教务打通**：对接青果教务系统（经统一身份认证 SSO），周视图课表、教务信息实时拉取；认证后按教务身份自动切换学生/教师角色，教务会话加密托管。

**AI 助手与知识库**：多供应商 AI 基座，六类模型能力（对话/视觉/语音识别/语音合成/向量/重排）管理端统一配置路由；SSE 流式输出；RAG 知识库"向量 + 词法"双通道混合召回、RRF 融合排序，检索结果注入对话上下文。

**生活服务**：电费查询（扫码绑定宿舍 + 低余额推送）、WebSocket 实时通知 + 统一收件箱。

## 技术架构

- **后端**：Spring Boot 3 / Java 17 / MySQL / Redis / Flyway 版本化迁移 / Spring Security 多角色会话与组织数据范围
- **客户端**：微信小程序原生开发；App 端 Flutter
- **管理端**：免构建原生 ES Module + Vue 3 / Element Plus，与后端同包静态直出
- **AI**：Provider 抽象 + OpenAI-compatible 适配器，供应商与默认模型管理端可配、可热切换
- **存储**：文件存储 local / MinIO / 阿里云 OSS 三实现热切换；RAG 使用独立 PostgreSQL
- **实时**：WebSocket 通知推送 + SSE 流式对话

### 工程亮点

- 统一 `Result<T>` 响应、全局异常处理、幂等键防重、雪花 ID 字符串化防精度丢失
- 密钥类配置（微信/QQ/SMTP/教务/高德/OSS 等）AES-256-GCM 加密落库，页面只显"已配置"不回显明文
- 社区行为表（收藏/隐藏）以唯一键防重，取消即删行，服务端为权威态，客户端写穿透缓存
- 图片全链路统一压缩；文件访问走 HMAC 短时签名 URL；敏感信息全程脱敏（手机号 `138****0000`、审计递归脱敏）

## 质量保障

- **接口一致性审计**：后端接口对前端调用逐一核对，0 断链
- **自动化测试**：后端 154 项测试（H2 内存库，不依赖本地环境）；App 端 93 项测试 + 静态分析 0 error；社区"收藏/隐藏/评论真实性/排序"均有专项回归测试
- **管理端冒烟**：真实登录 + 39 路由 + 校区切换自动化冒烟脚本
- **数据库演进**：Flyway 全量迁移管理，已应用迁移不可改、结构变化只增不改
