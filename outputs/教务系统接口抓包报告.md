# 绵阳城市学院教务系统（青果 Kingosoft）接口调研报告

> 调研日期：2026-08-29。方式：浏览器实际登录抓包（用户本人账号授权）。
> 用途：student-hub 小程序「课表导入」功能的后端实现依据。

## 结论

方案可行，完整链路已全部走通并验证两次登录成功。整体流程：

```
小程序 → student-hub 后端 → SSO(sso.mycc.edu.cn) → 教务系统(jwgl.mycc.edu.cn)
```

系统形态：SSO 为「统一身份认证平台」（mcauth），教务系统为**青果 Kingosoft 高校教学综合管理服务平台**，
课表数据接口参数仅做 **base64 编码（非加密）**，密码经 **RSA 公钥加密**（公钥写死在前端代码里）。
学校同时配有「喜鹊儿」App（本报告未抓 App 端，Web 端接口已足够）。

## 一、SSO 登录链路（后端需复刻）

### 1. 获取验证码

```
GET https://sso.mycc.edu.cn/mcauth/kaptcha?uid={uuid}
```

- 返回图片：**算术题验证码**（如「2 + 9 =」「7 * 0 =」），后端把图片转 base64 给小程序展示，用户口算后提交
- `{uuid}` 自行生成，登录时作为 `id` 参数原样传回，验证码与 id 绑定
- 后端需用同一个 HTTP 会话（Cookie 管理器）完成 kaptcha → tickets 两步

### 2. 登录换取 ticket

```
POST https://sso.mycc.edu.cn/mcauth/v1/tickets
Content-Type: application/x-www-form-urlencoded

username=2023590397
password={RSA加密后的hex，256字节/512个hex字符}
service=http%3A%2F%2Fjwgl.mycc.edu.cn%2Fcaslogin
loginType=
id={验证码uid}
code={验证码答案}
```

成功响应（HTTP 200，JSON）：

```json
{"tgt":"TGT-035722-xxxxxxxx","ticket":"ST-035722-xxxxxxxx"}
```

失败场景（验证码错/密码错）需实测确认响应结构（预计非 200 或 JSON 带 error 字段）。

### 3. RSA 加密细节

公钥写死在前端 bundle（app.xxx.js）常量模块中：

```
public_exponent: 010001
modulus(hex):
00b5eeb166e069920e80bebd1fea4829d3d1f3216f2aabe79b6c47a3c18dcee5fd22c2e7ac519cab59198ece036dcf289ea8201e2a0b9ded307f8fb704136eaeb670286f5ad44e691005ba9ea5af04ada5367cd724b5a26fdb5120cc95b6431604bd219c6b7d83a6f8f24b43918ea988a76f93c333aa5a20991493d4eb1117e7b1
```

- 2048 位 RSA，密文为 256 字节，hex 小写输出
- 填充方式**待验证**：此类前端一般用 jsencrypt（PKCS#1 v1.5 + UTF-8 明文），后端先用 PKCS#1 v1.5 试，登录失败再试 OAEP
- ⚠️ 前端 bundle 还泄露了 private_exponent（厂商构建失误），**不要使用也不要外传**，我们只需公钥做正常客户端行为

### 4. 用 ticket 换教务系统会话

```
GET http://jwgl.mycc.edu.cn/caslogin?ticket=ST-035722-xxxxxxxx
```

- 标准 CAS 校验：302 重定向链，最终落在 `/frame/homes.action?v=...`
- **跟随重定向 + Cookie Jar**，结束后持有的 jwgl.mycc.edu.cn JSESSIONID 就是教务系统登录态
- ticket 一次性，注意 ticket 在 query 里是明文，后端日志脱敏
- SSO 虽然传的是 http service 参数，但教务系统会跳转到 https，直接用 https 请求即可

## 二、课表数据接口

### 1. 个人课表页面（拿学期列表 + 内部学号）

```
GET https://jwgl.mycc.edu.cn/student/xkjg.wdkb.jsp?menucode=S20301&bqflag=1
```

从返回 HTML 中解析：

- **学期下拉 `#xnxq`**：option value 如 `2025-1`，text 如 `2025-2026学年第二学期`（新学期开放后选项会增加，遍历选项即可）
- **隐藏字段**：`xn`（学年起始年 2025）、`xn1`（学年结束年 2026）、`xq`（学期码 1）、`xh`（**教务内部学号**，如 202500002077，≠SSO 账号，必须从页面读取）

### 2. 课表数据（核心接口）

```
GET https://jwgl.mycc.edu.cn/student/wsxk.xskcb10319.jsp?params={base64}
params 明文 = "xn={学年始}&xq={学期码}&xh={内部学号}"
示例：xn=2025&xq=1&xh=202500002077
  → base64: eG49MjAyNSZ4cT0xJnhoPTIwMjUwMDAwMjA3Nw==
```

- 标准.base64（含 padding），URL 中原样传输（+ / = 需 urlEncode）
- **响应为 GBK 编码 HTML**，Java 端用 `Jsoup.parse(stream, "GBK", url)` 解析
- 二维表视图（默认）：最后一组 table，行=节次大节（一~五），列=星期一~星期日，
  单元格内多门课堆叠，每门课含：课程名/教师/`周次[节次]`/教室 容量
- **推荐用列表视图**（更好解析）：

```
GET https://jwgl.mycc.edu.cn/wsxk/xkjg.ckdgxsxdkchj_data10319.jsp?params={同上base64}
```

返回单张平铺表格，表头 12 列：

| 上课班级代码 | 课程 | 总学时 | 学分 | 修读性质 | 任课教师 | 选课状态 | 教材 | 上课时间地点 | 备注 |
|---|---|---|---|---|---|---|---|---|---|

（另有无表头的隐藏列：内部学号、年级代码等，行尾 4 个 td）

### 3. 「上课时间地点」列格式（解析重点）

一段字符串可含多个时段，用中文分号 `；` 分隔，每段格式：

```
{周次}周 {星期}[{节次}] {教学楼房间} {房间全名}({容量})
```

实测样例：

```
9,11-12周 二[1-4] 众立-105 无线网络数据采集部(90)；13周 一[5-8] 众立-110 电子技术实验室(80)
7-8周 三[5-6] 博雅-303(56)
2,4,6,12,14周(双) 日[1-4] 众立-101 集中技训室五(90)
1-3,5,8周 五[3-4] 信-202 计算机公共机房（安州）3（70台）(80)
```

解析规则：

- 周次：逗号分隔的数字/区间（`1-5,7-8`），可带 `(单)`/`(双)` 后缀；周日显示为「日」
- 节次：方括号区间 `[1-4]`，注意一节=小节（1-11 节），区间可能跨上午下午
- 同一门课可能拆多行（上课班级 009/010 = 单双班，分别覆盖不同周段），**全部入库**，显示层合并
- 教师格式 `[工号]姓名`，课程格式 `[课程代码]课程名`，都去掉方括号前缀存干净值（原始值可存 raw）

## 三、后端实现要点（student-hub）

1. **模块**：`modules/schedule`（entity/mapper/service/controller）+ `integration/jw`（青果客户端），
   HTTP 用 JDK HttpClient + CookieManager（整个登录链共用一个），HTML 解析加 Jsoup 依赖
2. **接口设计**（沿用项目 Result/鉴权体系）：
   - `GET /api/schedule/import/captcha` → 生成 uid，转发 kaptcha 图片(base64)，uid+Redis 暂存（5min TTL）
   - `POST /api/schedule/import` → 收 账号/密码/验证码，跑完整链路，解析入库（同用户同学期先删后插），密码不落库不写日志
   - `GET /api/schedule/mine` → 查已导入课表（不再访问教务系统）
3. **数据表**（V10 migration）：`schedule_course`：user_id, semester_code(2025-1), semester_name,
   course_code, course_name, teacher, class_code, location, day_of_week(1-7), start_section, end_section,
   weeks(varchar 原样), week_parity(0全部/1单/2双), credit, raw_text；另存一份原始 JSON/HTML 备重刷
4. **限流**：导入接口按用户+IP 限流（如 10 分钟 5 次），防止后端被当跳板爆破教务系统
5. **失败提示**：统一「账号、密码或验证码错误」，不透传教务系统原文

## 四、补充调研：心跳、调课监控与 JSON 接口（2026-08-29 第二轮）

### 1. 心跳机制：网页端没有主动心跳，会话是空闲超时型

- 主框架页脚本扫描（内联 + messages.js / homes.plus.js / AjaxBase.js / UserMenuBean.js / SetMainInfo.jsp）
  均无 setInterval 轮询；页面空闲 85 秒期间 performance 时间线零请求
- 会话存活性实测：登录后长时间闲置（几十分钟量级）会话仍有效，服务端空闲超时较宽松（具体阈值待后端实测）
- **后端保活不需要学校提供心跳接口**：任意已登录 GET 请求都会重置空闲计时。导入成功后，
  后端每 5-10 分钟拉一次课表页即可续命；建议给保活设上限（如 48h），到期让用户重新导入

### 2. 调课监控接口（解决「调课后数据过期」）

```
POST https://jwgl.mycc.edu.cn/student/jxap.jxaptzxx_rpt.jsp
Content-Type: application/x-www-form-urlencoded

xh={内部学号}&xn={学年起}&xn1={学年至}&xq={学期码}&_xq={第X学期}&xnxq={2025-1}&btnSubmit=检索
```

- 返回该学生**全部调课通知**（GBK HTML，每条通知一组 table）
- 每条含：调课时间（如 2026-06-09 09:16）、类型（停课/补课）、课程 `[M05S1015]Web项目开发综合实训`、
  上课班号、调课前后对比（周次/节次/地点/教师/授课方式）、上课班级构成、调课原因
- 调课信息页壳：`/student/jxap.jxaptzxx.html?menucode=S20302&bqflag=1`（参数由
  `/STU_DynamicInitDataAction.do?classPath=` 从会话注入，后端直接用已知值 POST 即可）

**推荐更新策略**：保活窗口内每次 ping 同时 ①重拉课表接口 diff ②拉调课通知按调课时间增量比对，
有变化 → 复用 modules/notification 推送小程序订阅消息「课表有调整」。会话过期后降级为
打开课表页时提示重新导入。

### 3. JSON 接口：学生 web 端没有，喜鹊儿通道不必碰

- 学生端 web 全是老式 JSP + 表单/XML（`STU_DynamicInitDataAction.do` 返回 XML），唯一 JSON 是 SSO 的
  `/mcauth/v1/tickets` 响应；没有可用的课表 JSON API
- 喜鹊儿 App 走厂商独立移动通道（非 jwgl web 端点），需要抓 App 包才能确认，且通常有签名/设备校验，
  合规面更模糊；web 端接口已覆盖全部需求，**不建议投入**
- 顺带发现：`/jw/common/showYearTerm.action`（主页面加载时调用）返回学年学期信息，可作为学期列表的备选来源

## 五、待验证清单（实现时确认）

- [ ] RSA 填充方式（PKCS#1 v1.5 优先）与明文编码（UTF-8）
- [ ] kaptcha→tickets 是否强制要求 SSO 域 Cookie 一致（CookieManager 全程带上即可）
- [ ] caslogin 302 链中间是否有额外 set-cookie 校验
- [ ] 验证码错误/密码错误的响应结构（决定后端错误映射）
- [ ] 服务器网络能否直达 sso/jwgl（校园网限制，部署前必测）
- [ ] 学期切换后 xn/xq 组合规则（新学期开放后抓一次即可）
- [ ] 教务会话空闲超时阈值与保活请求的最小频率（后端实测：登录后定时拉课表页，记录多少分钟断）
